- 变更记录：
  | 版本 | 日期 | 变更 |

  | v1.0 | 2026-08-10 | 首版：存量 3 个查询接口 + 订单事件推送的正式化文档 |

## 1. 环境与基础地址

| 环境 | Base URL | 说明 |
|---|---|---|
| 测试 | `https://testapi.aifupan.com.cn` | 可联调；数据为测试数据 |
| 生产 | `https://api.aifupan.com.cn` | 生产真实数据 |

完整请求地址 = Base URL + 接口路径（无额外路径前缀）。

## 2. 鉴权

所有接口走请求头 api-key 鉴权（仅限服务端间调用，凭证严禁下发到浏览器/客户端）：

| Header | 必填 | 说明 |
|---|---|---|
| `x-jiuyu-client-id` | 是 | 调用方应用 ID（为贵方独立分配，可独立轮换/吊销） |
| `api-key` | 是 | 应用密钥（通过配置渠道单独交付，**不随文档分发**） |
| `Content-Type` | POST 时必填 | `application/json` |

## 3. 通用响应与错误码

HTTP 状态码**恒为 200**，以响应体 `code` 判断结果：

```json
{ "code": 0, "msg": "", "data": { } }
```

| code | 含义 | 处理建议 |
|---|---|---|
| `0` | 成功 | 消费 `data` |
| `403` | 鉴权失败（header 缺失 / 密钥不匹配 / 应用未配置） | 检查两个鉴权 header；连续失败请联系我方核对密钥 |
| `-9` | 参数或业务校验失败（`msg` 含中文原因，如「phones数量不能超过50」） | 修正入参后重试，**不要**原样自动重试 |
| 其他非 0 | 服务端异常 | 可重试（建议指数退避，≤3 次）；持续失败联系我方 |

**判断成功的唯一标准是 `code == 0`**；`data` 为空对象/空数组不代表失败。

## 4. 通用数据口径

| 项 | 口径 |
|---|---|
| 时区 | 全部时间为北京时间（UTC+8）；事件推送为 ISO_OFFSET 格式（`2026-08-10T12:00:00+08:00`），查询接口内时间为 `yyyy-MM-dd HH:mm:ss` |
| ID 类型 | ⚠️ **存量接口**（本文档第 5–7 节）的 `userId`、订单 `id` 等以 **JSON 数值**（雪花 Long）返回，JS 侧直接 `JSON.parse` 会丢精度——请以字符串方式解析（如 `JSON.parse(text, reviver)` 或按文本提取）。**本期新增接口**（v1.1 补充）一律按字符串序列化，不存在此问题 |
| 批量上限 | 存量接口单次 ≤50 个手机号（超限返回 code=-9）；新增接口默认 ≤200 |
| 手机号 | 入参手机号做 trim + 去重后处理；响应按入参顺序回显 |
| 无数据语义 | 存量接口：身份不存在时 `exists=false`（聚合/订单接口另给 `missingReason=CUSTOMER_NOT_FOUND`）；行为信号接口未命中时数值字段填 0，**属早期契约**，请以 `exists` 为准判断，不要把 0 当真实用量。新增接口统一采用三态 `missingReason` 语义（v1.1 说明） |
| 限流建议 | 建议单调用方 ≤10 QPS；批量接口优先增大单批数量而非提高频率 |

## 5. 批量聚合查询客户信息

> `POST /internal/crm/customer/batch-aggregate-query`

**业务含义**：按手机号批量查询爱复盘侧的客户（用户）、归属销售与全部订单。是 CRM 客户 ↔ 爱复盘产品身份的**主入口映射接口**：返回的 `userId` 即爱复盘 `user_id`，一次查询即可建立「CRM 客户 → 产品用户」关联，请贵方持久化 `userId` 后不再依赖手机号查询。

### 请求

```json
{ "phones": ["13800000001", "13800000002"] }
```

| 字段 | 类型 | 必填 | 规则 |
|---|---|---|---|
| phones | string[] | 是 | 1–50 个；空串忽略；重复去重 |

### 响应 `data`

```json
{
  "customers": [
    {
      "phone": "13800000001",
      "exists": true,
      "missingReason": null,
      "userId": 1811111111111111111,
      "customerName": "张三",
      "sales": { "id": 1, "salesName": "李四", "phone": "139...", "salesType": 0, "employeeStatus": 0 },
      "orders": [ { "...": "见 §5.3 订单对象" } ]
    },
    { "phone": "13800000002", "exists": false, "missingReason": "CUSTOMER_NOT_FOUND", "orders": [] }
  ]
}
```

| 字段 | 类型 | 口径 |
|---|---|---|
| phone | string | 回显入参 |
| exists | boolean | 手机号是否命中爱复盘用户（精确匹配注册手机号） |
| missingReason | string | 未命中时固定 `CUSTOMER_NOT_FOUND`；命中时不返回 |
| userId | number(Long) | 爱复盘用户 ID（产品 `user_id`，与 open-stats 的 `userIds` 同一体系，可直接互查）。⚠️ 精度见 §4 |
| customerName | string | 用户昵称（非实名） |
| sales | object | 归属销售；无归属时为 null。关键字段：`salesName` / `phone` / `employeeStatus`（0 在职 1 离职） |
| orders | array | 该用户**全部订单**（含免费、试用、各状态，软删除除外），排序为我方内部默认序。正式成交判定见 §5.3 |

### 5.3 订单对象（orders[] 元素，三个接口共用）

核心字段（其余字段为内部运营字段，未列出的请勿消费）：

| 字段 | 类型 | 口径 |
|---|---|---|
| id | number(Long) | 订单号（雪花 ID，即事件推送里的 `orderId`），**幂等去重键** |
| userId | number(Long) | 下单用户 |
| commodityId / commodityName / title | — | 商品与订单标题 |
| status | int | 订单状态：0 未支付 / 1 未开始 / 2 生效中 / 3 已过期 / 4 已退款 / 5 已结束（升级后旧单失效）/ 6 超时未支付关闭 / 7 冻结 / 8 手动取消 |
| orderType | int | 0 免费 / 1 升级 / 2 免费版换收费版 / 3 续费 / 4 增量包 / 5 版本活动 / 6 编辑 / 7 商品活动 |
| commodityType | int | 0 增量包 / 1 正常版本 / 2 活动版本 / 3 邀请活动 |
| source | int | 来源：**0 正常下单** / 1 后台手动添加 / 2 邀请用户成功 / 3 邀请码赠送。`source≠0` 的订单**没有支付流水**，不能计为「曾正式支付」 |
| trialOrder | int | 1 = 试用订单（不计正式成交），0 = 非试用 |
| totalPrice | int | **实付金额，单位分**（即事件里的 `priceCent`）。`realPrice`/`originalPrice` 是挂牌价/原价，不能当实付用。币种恒为人民币 |
| payDate | datetime | 支付成功业务时间；无支付则为 null |
| startDate / endDate | datetime | 服务生效/到期时间 |
| createDate / updateDate | datetime | 订单创建/最后更新时间 |
| orderPay | object | 支付流水。可信字段：`payStatus`（1=支付成功）/ `payType` / `payMoney`(分) / `payDate` / `thirdOrderNum`。⚠️ 其中 `refund*` 系列字段为**未启用的占位字段**（退款走线下，系统不写入），请勿消费 |

**「曾正式支付」推荐判定**：`trialOrder=0` 且 `source=0` 且 `payDate` 非空（等价于 `orderPay.payStatus=1`）。
**「当前是否有效」**：以 `status` 为准（2 生效中）；退款/取消事实的线上化在二期建设中，在此之前 `status=4/8` 的变更时间点不可考。

## 6. 按手机号查询订单

> `GET /internal/crm/order/query-by-phone?phone=13800000001`

**业务含义**：单手机号的订单专用查询，返回结构比聚合接口轻（无销售、无昵称）。适合对单个客户做订单核对；批量场景请用 §5。

### 响应 `data`

```json
{
  "phone": "13800000001",
  "exists": true,
  "missingReason": null,
  "userId": 1811111111111111111,
  "orders": [ { "...": "同 §5.3 订单对象" } ]
}
```

字段口径与 §5 完全一致；未命中时 `exists=false` + `missingReason=CUSTOMER_NOT_FOUND`、`orders=[]`。

## 7. 批量查询客户行为信号（试用期使用深度）

> `POST /internal/crm/customer/behavior-signals`

**业务含义**：按手机号批量返回该客户**所在团队（租户）**的产品使用深度信号，用于销售侧判断试用活跃度。统计维度是「该用户当前激活租户」的团队合计，不是个人维度。

### 请求

```json
{ "phones": ["13800000001"] }
```

phones：1–50 个，规则同 §5。

### 响应 `data`

```json
{
  "signals": [
    {
      "phone": "13800000001",
      "exists": true,
      "customerUnitSize": 3,
      "addedAnchorCount": 5,
      "ownAnchorCount": 2,
      "hasUsedOpAssistant": true,
      "hasUsedCompareReplay": false,
      "serviceDurationHours": 720,
      "aiAnalysisTimeConsumed": 36000,
      "totalAiTokensUsed": 1234567,
      "recentAiTokensUsed30d": 23456,
      "recentAiTokensUsed7d": 3456
    }
  ]
}
```

| 字段 | 类型 | 口径 |
|---|---|---|
| exists | boolean | 手机号是否命中用户。**false 时以下数值字段填 0，不代表真实用量** |
| customerUnitSize | int | 团队账号总数（主账号 + 子账号，按当前激活租户统计） |
| addedAnchorCount | int | 团队添加的直播间账号总数（**不分平台**；分平台的租户×平台口径由 v1.1 新接口提供） |
| ownAnchorCount | int | 其中「自有账号」数 |
| hasUsedOpAssistant | boolean | 团队历史上是否用过运营助手（旧版 App 助手） |
| hasUsedCompareReplay | boolean | 团队历史上是否用过对比复盘 |
| serviceDurationHours | int | 主账号注册至今的小时数 |
| aiAnalysisTimeConsumed | long | 团队累计**音视频转写时长（秒）**——资源消耗口径，不是「分析状态」；分析状态由 v1.1 新接口提供 |
| totalAiTokensUsed / recentAiTokensUsed30d / recentAiTokensUsed7d | long | ⚠️ 旧版 App AI 助手的算力台账口径，**与 open-stats 的 billedTokens 是两套数据，不可相加、不可互替**。该组字段仅供销售参考，请勿用于统计对账 |

**边界**：用户存在但无有效租户时，`exists=true` 且数值字段为 0（真实为空团队）。

## 8. 订单事件推送（出站，PAY_SUCCESS）

**业务含义**：订单支付成功后，爱复盘主动向订阅方推送事件。当前现状如实说明：

- 仅 `PAY_SUCCESS` 一种事件类型；退款/取消**无事件**（二期建设）；
- 推送为进程内直发、**无重试补偿**——推送可能遗漏，**请以拉取对账为准、事件为提速手段**（对账拉取接口随 v1.1 交付）；
- 当前订阅方为 CRM 系统；贵方如需订阅同一事件流，请提供回调地址与验签方式，我方配置后生效。

### 推送报文

```json
{
  "eventId": "order_evt_1811111111111111111_1723190400000",
  "eventType": "PAY_SUCCESS",
  "occurredAt": "2026-08-10T12:00:00+08:00",
  "customer": { "phone": "13800000001", "userId": "1811111111111111111" },
  "sales": { "salesPhone": "13900000001", "salesId": "1" },
  "order": {
    "orderId": "1811111111111111111",
    "orderType": "RENEWAL",
    "commodityType": "VERSION",
    "isTrial": false,
    "status": "ACTIVE",
    "startTime": "2026-08-10T12:00:00+08:00",
    "endTime": "2027-08-10T12:00:00+08:00",
    "priceCent": 99900
  }
}
```

| 字段 | 口径 |
|---|---|
| eventId | ⚠️ 现为 `order_evt_{orderId}_{发布时刻毫秒}`，**同一业务事件补发时会变化**——请勿以 eventId 做业务幂等，**以 `order.orderId` 去重**。已列入整改：改为按支付业务时间构造，整改完成前请保持 orderId 去重口径 |
| eventType | 目前恒为 `PAY_SUCCESS` |
| occurredAt | 事件业务时间（ISO_OFFSET，UTC+8） |
| customer.userId / order.orderId / sales.salesId | 事件侧已按**字符串**序列化，无精度问题 |
| order.orderType | 字符串枚举：`FREE / UPGRADE / RENEWAL / INCREMENT / ACTIVITY`（由 §5.3 的 int `orderType`+`commodityType` 映射） |
| order.commodityType | `VERSION`（版本套餐）/ `INCREMENT`（增量包） |
| order.status | 字符串枚举：`PAID / ACTIVE / EXPIRED / REFUNDED / CANCELED`（映射：2→ACTIVE，3→EXPIRED，4→REFUNDED，5/6/7/8→CANCELED，其余→PAID） |
| order.isTrial | true = 试用订单 |
| order.priceCent | 实付金额（分）= 订单 `totalPrice` |

## 9. 已知限制与建设计划（如实声明）

| # | 事项 | 现状 | 计划 |
|---|---|---|---|
| 1 | 存量接口 Long ID 为 JSON 数值 | 精度风险需调用方规避（§4） | 新增接口一律字符串；存量接口保持现状不破坏既有调用方 |

# 第二部分：v1.1 新增接口（/internal/data-hub）

## 11. 新增接口通用约定

以下 7 个接口为本期面向 Business Data Hub 新建，统一约定（覆盖 §4 中对存量接口的描述）：

| 项 | 约定 |
|---|---|
| 路径前缀 | `/internal/data-hub`，全部 `POST` + JSON body |
| 鉴权 | 同 §2（独立 app-id 随联调开通交付） |
| ID 序列化 | 响应中所有用户/租户/订单 ID **一律字符串**，无精度问题；请求中的 ID 数组用 JSON 数值或字符串均可 |
| 批量上限 | 各 ID 列表 ≤200（超限 code=-9 报错，不静默截断） |
| 时间 | 入参窗口字符串 `yyyy-MM-dd HH:mm:ss`，**左闭右开** `[startTime, endTime)`，两端均可省略；响应时间同格式（UTC+8） |
| 无数据语义 | 三态：`missingReason=null`（命中，数值为真实值，真实零表现为 0/false/空数组）/ `NOT_FOUND`（身份不存在）/ `NOT_MAPPED`（仅映射接口：用户存在但无激活租户）。参数/系统错误走非 0 `code`，绝不与业务缺失混用 |
| 结果顺序 | `items[]` 与入参 ID 列表一一对应、保序（入参先去空去重） |

## 12. 客户→租户映射

> `POST /internal/data-hub/customer/tenant-mapping`

**业务含义**：把 CRM 侧客户（手机号或已持久化的 userId）映射到爱复盘产品租户。返回**当前**关系（单一激活租户模型，见 Contract 补充确认第 4 条）；历史关系请用 §13 成员名单的 joined/left 时间推导。映射建立后请持久化 `tenantId`/`userId`，不再依赖手机号。

### 请求（phones / userIds 至少传一个，合计 ≤200）

```json
{ "phones": ["13800000001"], "userIds": ["1811111111111111111"] }
```

### 响应 `data.items[]`

| 字段 | 类型 | 口径 |
|---|---|---|
| phone | string | 按手机号查询时回显；按 userId 查询时无此字段 |
| userId | string | 产品用户 ID（未命中时按 userId 查询会回显入参） |
| tenantId | string | 当前激活租户 ID |
| relationStatus | string | `MAIN` 主账号 / `SUB` 子账号 |
| accountStatus | string | `NORMAL` 正常 / `FROZEN` 已冻结 |
| missingReason | string | `null` 命中 / `NOT_FOUND` 用户不存在或已注销 / `NOT_MAPPED` 用户存在但无激活租户（极少数早期数据） |
| sourceUpdatedAt | datetime | 用户数据最后更新时间 |

**口径**：一个租户固定一个主账号；多个 CRM 联系人（子账号手机号）会映射到同一 `tenantId`，属正常情况，请以租户为聚合键。成员换绑后本接口返回新租户。

## 13. 租户成员名单

> `POST /internal/data-hub/tenant/members`

**业务含义**：按租户批量拉全量成员——含**当前成员**（正常/冻结/已删除）与**已解绑成员**，不静默丢失任何历史成员。返回的 `userId` 与 open-stats 的 `userIds` 同一体系，可直接互查。

### 请求

```json
{ "tenantIds": ["1811111111111111111"] }
```

### 响应 `data.items[].members[]`

| 字段 | 类型 | 口径 |
|---|---|---|
| userId | string | 成员用户 ID |
| role | string | `MAIN` 主账号 / `SUB` 子账号 |
| status | string | `NORMAL` / `FROZEN` 冻结 / `DELETED` 已删除 / `UNBOUND` 已解绑（离开租户） |
| displayName | string | 昵称（已注销的解绑成员可能为空） |
| maskedPhone | string | 脱敏手机号（如 `138****0001`）；完整手机号不经本接口下发 |
| hasLoggedIn | boolean | 是否登录过 |
| registeredAt | datetime | 注册时间 |
| joinedAt | datetime | 加入租户时间：主账号=注册时间；子账号=绑定时间。**早期数据无绑定记录时为空**，空值含义=「加入时间不可考」，不代表未加入 |
| leftAt | datetime | 离开租户时间（仅 `UNBOUND` 成员），=解绑时间 |

**口径**：`items[].missingReason=NOT_FOUND` 表示租户不存在。租户存在但只有主账号一人时 members 只有一条（真实情况）。

## 14. 成员登录状态

> `POST /internal/data-hub/user/login-stats`

**业务含义**：按用户批量聚合登录事实。数据源为登录日志（每次**成功**登录一行）；**登录失败不落日志，无法提供失败次数**。

### 请求

```json
{ "userIds": ["1811111111111111111"], "startTime": "2026-07-01 00:00:00", "endTime": "2026-08-01 00:00:00" }
```

startTime/endTime 可省略；省略时仅返回累计口径。

### 响应 `data`

顶层 `windowStart` / `windowEnd` 回显实际生效窗口；`items[]`：

| 字段 | 类型 | 口径 |
|---|---|---|
| userId | string | 用户 ID |
| missingReason | string | `null` / `NOT_FOUND`（用户不存在或已注销） |
| hasLoggedIn | boolean | 历史上是否成功登录过（冗余标记 ∪ 日志计数 > 0） |
| firstLoginAt / lastLoginAt | datetime | 首次/最近成功登录时间（累计口径，不受窗口影响） |
| totalLoginCount | long | 累计成功登录次数 |
| windowLoginCount | long | 窗口内成功登录次数；未传窗口时无此字段 |

**已知限制**：日志表自上线起完整；**最早可信日期**待查证生产库后书面补充（在此之前请勿以 firstLoginAt 判断"注册即活跃"类口径）。

## 15. 业务账号汇总与明细

> `POST /internal/data-hub/tenant/business-accounts`

**业务含义**：按租户返回添加的直播间业务账号（抖音/快手/视频号）——租户×平台汇总 + 逐条明细。响应 `observedAt` 为实时快照时间。

### 请求

```json
{ "tenantIds": ["1811111111111111111"], "includeRemoved": false }
```

`includeRemoved=true` 时明细额外包含已移除账号（汇总恒为在册口径）。

### 响应 `data.items[]`

- `summary[]`：`{ platform, totalCount }`——**在册数**（未从列表移除）。无独立"有效"概念，故不提供 `activeCount`（避免返回与 totalCount 恒等的冗余字段）。
- `accounts[]`：

| 字段 | 类型 | 口径 |
|---|---|---|
| businessAccountId | string | 平台侧稳定 ID（sec_uid）。唯一键 = `platform + businessAccountId` |
| nickname | string | 账号昵称 |
| platform | string | `DOUYIN` / `KUAISHOU` / `WECHAT_CHANNELS` |
| accountType | string | `OWN` 自有账号 / `PEER` 同行账号 |
| addedByUserId | string | 添加人用户 ID（仅表示操作者） |
| addedAt | datetime | 添加时间 |
| removed | boolean | 是否已从列表移除 |
| removedAt | datetime | 移除时间（仅已移除） |

**口径**：同一业务账号可被同租户多个成员分别添加，明细**每条添加关系一行**；按账号去重请用 `platform+businessAccountId`。

## 16. 授权状态

> `POST /internal/data-hub/tenant/authorizations`

**业务含义**：返回四类授权（巨量百应/千川/微信视频号/抖音来客）的**现状**。粒度 = 租户 × 成员 × 业务账号 × 授权类型（每个在册账号固定 4 行）。

### 请求

```json
{ "tenantIds": ["1811111111111111111"] }
```

### 响应 `data.items[].authorizations[]`

| 字段 | 类型 | 口径 |
|---|---|---|
| businessAccountId | string | 业务账号 sec_uid |
| operatorUserId | string | **授权记录归属成员**（该账号添加关系的所属成员），不保证是实际点授权的人 |
| authType | string | `JULIANG_BAIYING` / `QIANCHUAN` / `WECHAT_CHANNELS` / `DOUYIN_LAIKE` |
| status | string | `NOT_AUTHORIZED` 从未/未授权 / `AUTHORIZED` / `EXPIRED` / `FAILED` / `AUTHORIZING` / `ACCOUNT_MISMATCH` 授权抖音号不匹配；`WECHAT_CHANNELS` 专有：`CANCELED_BY_WECHAT` / `CANCELED_BY_USER` |
| statusUpdatedAt | datetime | 状态变更时间。**`WECHAT_CHANNELS` 模型无此字段，恒为空**（空=无数据，不用其他时间代替）；数据新鲜度请以响应到达时刻视为现状快照 |

**已知限制（如实声明，二期项）**：无 `authorizedAt`（首次授权时间不可回溯，状态=AUTHORIZED 时 statusUpdatedAt 近似最近授权时间）；无 `expiresAt`（过期只能由 EXPIRED 状态表达）；无授权历史流水。

## 17. 账号分析状态

> `POST /internal/data-hub/tenant/analysis-stats`

**业务含义**：直播录像**智能分析**的成功记录，按 租户 × 业务账号 聚合。这是「分析行为状态」口径，与 behavior-signals 的 `aiAnalysisTimeConsumed`（转写时长资源口径）是两回事。本期仅覆盖直播侧；短视频/达人分析如需要请另行确认。

### 请求

```json
{ "tenantIds": ["1811111111111111111"], "startTime": "2026-07-01 00:00:00", "endTime": "2026-08-01 00:00:00" }
```

窗口按**分析完成时间**过滤，可省略（=全历史累计）。

### 响应 `data.items[].accounts[]`

| 字段 | 类型 | 口径 |
|---|---|---|
| businessAccountId | string | 业务账号 sec_uid |
| analysisCount | long | 窗口内成功分析次数（未传窗口=累计） |
| firstAnalyzedAt / lastAnalyzedAt | datetime | 窗口内首次/最近成功分析时间 |

**口径**：从未成功分析过的账号**不出现在** `accounts[]`（真实零 = 空缺）；`items[].missingReason=NOT_FOUND` 才表示租户不存在。极少数早期记录分析时间为空：计入 analysisCount，但不参与 first/last 计算。

## 18. 订单增量对账拉取

> `POST /internal/data-hub/order/reconciliation`

**业务含义**：订单事实的**增量对账主通道**。事件推送（§8）无重试补偿，请以本接口为准：建议定时（如每 5–15 分钟）按水位增量拉取，`orderId` 幂等去重覆盖更新。软删除订单不返回。

### 请求

```json
{
  "tenantIds": ["1811111111111111111"],
  "updatedAfter": "2026-08-01 00:00:00",
  "cursor": null,
  "pageSize": 200
}
```

| 字段 | 必填 | 口径 |
|---|---|---|
| tenantIds | 否 | ≤200；**不传 = 全平台全租户对账**。该口径仅授权给对账用途的合作方 app-id（本接口权限模型为 7 个接口中最宽），如贵方仅需部分租户请显式传 tenantIds |
| updatedAfter | 否 | 增量起点（含），按订单**最后更新时间**。建议每轮用「上轮最大 updatedAt − 5 分钟」防丢 |
| cursor | 否 | 翻页游标：第一页不传，之后原样回传上一页 `nextCursor`（对调用方不透明，勿解析勿构造） |
| pageSize | 否 | 1–500，默认 200 |

### 响应 `data`

`items[]`（按 updatedAt,orderId 升序）+ `nextCursor` + `hasMore`。同一轮拉取中**换页必须带同一 updatedAfter**；数据在翻页间被更新会在后续增量轮次重新出现（以 orderId 覆盖即可）。

| 字段 | 类型 | 口径 |
|---|---|---|
| orderId | string | 订单号，幂等去重键，与事件 `order.orderId` 一致 |
| userId | string | 下单用户 |
| tenantId | string | 归属租户；无法归属时为 null |
| tenantAttribution | string | `SNAPSHOT` 业务时点快照 / `BACKFILLED` 按当前关系回填（历史数据）/ `UNKNOWN` 无法归属。切换时间点确认前，可归属数据统一保守标记为 `BACKFILLED`；切换时间点书面确认后新单改标 `SNAPSHOT`（届时另行通知） |
| status | string | 细粒度：`UNPAID` / `NOT_STARTED` / `ACTIVE` / `EXPIRED` / `REFUNDED` / `ENDED_BY_UPGRADE` / `CLOSED_TIMEOUT` / `FROZEN` / `CANCELED_MANUAL`。与事件侧折叠枚举对照：事件 `CANCELED` = 本接口 `ENDED_BY_UPGRADE|CLOSED_TIMEOUT|FROZEN|CANCELED_MANUAL`；事件 `PAID` = 其余非 ACTIVE/EXPIRED/REFUNDED 态 |
| orderType | string | `FREE` / `UPGRADE` / `FREE_TO_PAID` / `RENEWAL` / `INCREMENT` / `VERSION_ACTIVITY` / `EDIT` / `COMMODITY_ACTIVITY`（事件侧 `ACTIVITY` = `VERSION_ACTIVITY|COMMODITY_ACTIVITY`） |
| commodityType | string | `INCREMENT` / `NORMAL_VERSION` / `ACTIVITY_VERSION` / `INVITE_ACTIVITY` |
| source | string | `NORMAL` 正常下单 / `MANUAL` 后台手动添加（无支付流水）/ `INVITE_REWARD` / `INVITE_CODE` |
| isTrial | boolean | 试用订单 |
| priceCent | int | 实付金额（分） |
| paidAt | datetime | 支付成功时间；`MANUAL` 等无支付订单为 null |
| serviceStartAt / serviceEndAt | datetime | 服务起止 |
| createdAt / updatedAt | datetime | 创建/最后更新时间（updatedAt 即增量与游标基准） |
| commodityName / title | string | 商品名 / 订单标题 |

**「曾正式支付」判定（与 §5.3 一致）**：`isTrial=false && source=NORMAL && paidAt != null`。
**退款/取消提醒**：`REFUNDED`/`CANCELED_MANUAL` 是当前状态标记，**变更时间不可考、无事件推送**（二期建设），请勿用 updatedAt 当退款时间。
