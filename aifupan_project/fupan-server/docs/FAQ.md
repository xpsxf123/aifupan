## 一、订单系统

### Q1: 订单为空时出现空指针异常

- **问题**: 订单处理时未做空判断导致NPE
- **修复**: commit `3acd6c1b1`，增加订单为空时的空指针保护
- **涉及文件**: OrderBll

### Q2: 免费订单创建时用户信息设置失败

- **问题**: 免费订单创建时用户信息设置不正确
- **修复**: commit `17abc445d`
- **涉及文件**: OrderBll

### Q3: 订单定时任务性能问题

- **问题**: 批量过期订单处理性能不佳
- **优化记录**:
  - `03eab0528`: 优化批处理大小
  - `0989856fc`: 优化并发处理逻辑
  - `e43ac330e`: 修正默认过期时间计算逻辑
- **建议**: 关注批处理大小配置，避免单次处理过多订单

### Q4: 订单过期处理的事务问题

- **问题**: 事务注解导致事务冲突
- **修复**: `d1183c08d` 移除订单过期处理中的事务注解
- **注意**: 过期处理涉及多个独立操作，不适合放在同一个大事务中

### Q5: 订单处理中的数据源错误

- **问题**: 订单处理使用了错误的数据源
- **修复**: commit `b714c445a`

## 八、技术债务

### 已知问题

1. **敏感信息明文存储**: Redis密码、第三方API密钥等明文存储在配置文件中，建议全部使用Jasypt加密
2. **payController类名不规范**: 首字母小写，不符合Java命名规范
3. **replay-reward模块拼写错误**: `contraller` 目录名拼写错误（应为controller）
4. **部分Controller被注释禁用**: replay-api中的邀请活动相关Controller已注释，功能迁移到各业务模块
5. **测试覆盖不足**: 项目中测试代码较少，建议补充核心业务的单元测试

### 性能关注点

1. 订单批量过期处理的批次大小需要根据数据量调整
2. Redis降级机制已实现，但需要监控降级频率
3. AI调用有QPS限制（语音识别30 QPS），需要注意限流
4. MongoDB查询需要关注索引优化
