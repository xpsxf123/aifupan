# PRD - 第三方接口：按行业随机获取直播录制记录

## 一、需求背景

为第三方合作方提供一个开放接口，根据行业ID随机返回3-5条直播录制记录，用于展示或数据对接。

## 二、接口定义

### 基本信息
- **接口路径**: `POST /replay/openapi/thirdparty/randomLiveRecords`
- **鉴权方式**: 复用现有签名机制（SignatureConfig，appId + appSecret + timestamp 签名验证）
- **请求Content-Type**: application/json

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| tradeId | Long | 是 | 行业ID（关联已有 tb_trade 表，支持任意层级） |

### 响应参数

```json
{
  "code": 0,
  "msg": "success",
  "data": [
    {
      "cloudUrl": "https://xxx.com/video/xxx.mp4",
      "viewers": 15000,
      "monthlySales": "100万-500万"
    }
  ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| cloudUrl | String | 云空间链接 |
| viewers | Long | 场观 |
| monthlySales | String | 月销售额（区间值，如"100万-500万"） |

> 不返回任何用户相关信息、主播信息（昵称、抖音号等均不暴露）

## 三、业务规则

### 3.1 数量控制
服务端固定随机返回3-5条记录，第三方无法指定数量

### 3.2 数据过滤条件（所有查询步骤通用）
- 记录未被删除（is_deleted = 0）
- 云空间链接不为空（cloud_url IS NOT NULL AND cloud_url != ''）

### 3.3 行业匹配逻辑（四级降级查询）

```
第1步：精确匹配
  └─ 用 tradeId 直接查记录表
      ├─ 有结果 → 随机取3-5条返回
      └─ 无结果 → 进入第2步

第2步：向下查子级
  └─ 用 tradeId 去 tb_trade 查所有子级行业ID（递归）
      └─ 用子级ID集合查记录表
          ├─ 有结果 → 随机取3-5条返回
          └─ 无结果 → 进入第3步

第3步：向上查父级
  └─ 用 tradeId 去 tb_trade 查所有上级行业ID（逐级向上）
      └─ 用父级ID集合查记录表
          ├─ 有结果 → 随机取3-5条返回
          └─ 无结果 → 进入第4步

第4步：兜底随机
  └─ 忽略行业条件，从全表随机取3-5条返回
```

### 3.4 随机策略
从符合条件的记录中随机抽取，每次请求结果不同

### 3.5 边界情况
- 全表无任何有效记录：返回空数组
- tradeId 在 tb_trade 中不存在：仍按第1步精确匹配记录表，无结果则直接跳到第4步兜底

## 四、鉴权说明

复用现有 SignatureConfig 签名机制：
- 第三方需分配独立的 appId + appSecret
- 请求头携带签名信息（appId、timestamp、sign）
- 签名过期时间：15分钟
- 接口路径需加入 SignatureConfig 的 includePaths 配置

## 五、数据表

### 已有表: tb_trade（行业表）

复用系统已有的行业表，树形结构通过 parent_id 关联，记录表的 trade_id 关联此表的 id。

### 新增表: tb_thirdparty_live_record（第三方直播录制记录表）

```sql
CREATE TABLE tb_thirdparty_live_record (
  id BIGINT NOT NULL AUTO_INCREMENT COMMENT '记录ID',
  trade_id BIGINT NOT NULL COMMENT '行业ID，关联tb_trade.id',
  anchor_nickname VARCHAR(100) DEFAULT NULL COMMENT '主播抖音昵称',
  douyin_id VARCHAR(100) DEFAULT NULL COMMENT '抖音号',
  cloud_url VARCHAR(500) DEFAULT NULL COMMENT '云空间链接',
  viewers BIGINT DEFAULT 0 COMMENT '场观',
  monthly_sales VARCHAR(100) DEFAULT NULL COMMENT '月销售额（区间值，如100万-500万）',
  create_date DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  update_date DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  is_deleted TINYINT DEFAULT 0 COMMENT '是否删除 0否 1是',
  PRIMARY KEY (id),
  INDEX idx_trade_id_deleted (trade_id, is_deleted)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='第三方直播录制记录表';
```

## 六、非功能需求

1. **限流**: 按appId限流，每秒最高10次，每分钟最高60次（基于Redis实现滑动窗口或令牌桶）
2. **性能**: 随机查询使用 `ORDER BY RAND() LIMIT n`，数据量大时可优化为先查ID再随机取。行业表数据量小，递归查子行业可用内存缓存

## 七、涉及改动

1. **新增**: tb_thirdparty_live_record 表
2. **新增**: Controller / Logic / Bll / Service / Dao / Entity / Vo 全链路代码
3. **新增**: 限流组件（基于Redis，按appId维度，秒级10次+分钟级60次双重限流）
4. **复用**: tb_trade 表及已有的行业树查询能力（查子级、查父级）
5. **配置**: SignatureConfig 中为第三方分配 appId+appSecret，接口路径加入 includePaths
6. **配置**: LoginInterceptor 的 excludePathList 中添加该接口路径（第三方无需登录）
