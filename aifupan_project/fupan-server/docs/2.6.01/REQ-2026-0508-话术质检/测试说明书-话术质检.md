## 5.5 reportStatus 契约改造 + secUid + summary String JSON（8 用例）

> **2026-06-02 变更**：
> 1. reportStatus 由 `GET + Query` 改为 `POST + JSON Body`
> 2. 新增可选字段 `secUid` 驱动 `monitorEnabled`
> 3. `summary` 字段类型**最终改为 String**（含原始 JSON 字符串，前端 `JSON.parse` 后取字段）— 此前曾短暂改为嵌套 Object，后回退为 String 减少前后端 schema 耦合
> 4. `qualityReportDetail` 顶层 4 个 count 字段合并到 `summaryJson` 字段（String）

### TC-RS-001 [P0] reportStatus — POST 契约（替换原 GET）

**前置**：测试租户已登录，有 sourceId=V 的视频已生成 3 类报告（status=2）。

**步骤**：
```
POST /replay/script-monitor/reportStatus
Content-Type: application/json
body: { sourceType: 0, sceneType: 0, sourceId: V }
```

**期望**：HTTP 200；`data.monitors` 数组 3 条；每条 `summary` 是 Object 不是 String；`monitorEnabled` 全为 null（未传 secUid）。

### TC-RS-002 [P0] reportStatus — GET 已废弃

**步骤**：用 GET + Query 调旧契约 `GET /replay/script-monitor/reportStatus?sourceType=0&...`。

**期望**：405 Method Not Allowed（或 404）。前端必须改用 POST。

### TC-RS-003 [P0] reportStatus — secUid 命中三开关 0/1 混合

**前置**：sec=S1 的直播间 `isScriptQualityInspection=1 / isScriptFidelityMonitor=0 / isInteractionPatrol=1`。

**步骤**：
```
POST /replay/script-monitor/reportStatus
body: { sourceType: 0, sceneType: 0, sourceId: V, secUid: S1 }
```

**期望**：`monitors[monitorType=0].monitorEnabled=1`、`monitors[monitorType=1].monitorEnabled=0`、`monitors[monitorType=2].monitorEnabled=1`。

### TC-RS-004 [P0] reportStatus — secUid 查无 anchor_url_user 记录

**前置**：传入一个当前用户名下不存在的 secUid=S_NOT_EXIST。

**期望**：接口正常返回 200，三个 `monitorEnabled` 全 null（不抛错；语义"不适用"）。

### TC-RS-005 [P0] reportStatus — 上传文件场景

**前置**：sourceType=1 + 一个 fileId（不传 secUid）。

**期望**：HTTP 200；三个 `monitorEnabled` 全 null。

### TC-RS-006 [P0] reportStatus — summary 是 String 含 JSON（不是 Object）

**前置**：质检报告 status=2，DB summary_json 列含 `{"crashCount":0,"slackCount":2,"brandDamageCount":0,"afterSalesCount":1,"totalNegativeCount":3,"overallScore":85}`。

**期望**：`typeof monitors[monitorType=0].summary === 'string'`；`JSON.parse(summary).crashCount === 0` 且包含 AI 原始返回的全部字段（含可选 totalNegativeCount / overallScore）。

### TC-RS-007 [P0] reportStatus — AI 返回非法 JSON 时 summary=null

**前置**：构造 AI 调用 mock 返回纯文本"非 JSON"，触发 buildSummary catch 分支。

**期望**：报告 status=GENERATED 但 `summary === null`（不是空字符串、不是 "{}"），主流程不抛异常，returnAiToken 未被调用。

### TC-RS-008 [P0] reportStatus — AI 返回 JSON 但无 summary key

**前置**：AI mock 返回 `{"details":[...],"summaryHtml":"..."}`（合法 JSON 但缺 summary key）。

**期望**：报告 status=GENERATED，`summary === null`，log.warn 记录"无 summary 段"，主流程不阻塞。

## 5.6 batchReportStatus 契约对齐（7 用例）

> 2026-06-02 变更：`SourceItem` 加可选 `secUid`；响应 `monitors[]` 同步加 `monitorEnabled` + `summary` 改为 String 含 JSON（与单接口一致）。

### TC-BRS-001 [P0] batchReportStatus — 单 secUid 全部 source 用同一 secUid

**前置**：3 个 sourceId 都属于同一 secUid=S1，isScriptQualityInspection=1。

**步骤**：
```
POST /replay/script-monitor/batchReportStatus
body: { sources: [
  { sourceType: 0, sceneType: 0, sourceId: V1, secUid: S1 },
  { sourceType: 0, sceneType: 0, sourceId: V2, secUid: S1 },
  { sourceType: 0, sceneType: 0, sourceId: V3, secUid: S1 }
]}
```

**期望**：3 条结果；每条 `monitors[monitorType=0].monitorEnabled=1`。DB 层：仅 1 次 `tb_anchor_url_user` IN 查询（看 SQL log）。

### TC-BRS-002 [P0] batchReportStatus — 多 secUid 混合

**前置**：sourceId V1→secUid S1（质检开），V2→secUid S2（质检关），V3 无 secUid。

**步骤**：3 条 sources，前 2 条带 secUid，第 3 条不带。

**期望**：V1.monitorType=0.monitorEnabled=1、V2.monitorType=0.monitorEnabled=0、V3.monitorType=0.monitorEnabled=null。

### TC-BRS-003 [P0] batchReportStatus — 部分 source 不带 secUid

**前置**：5 条 sources，3 条带 secUid（同一个 S1），2 条不带。

**期望**：3 条带 secUid 的 monitorEnabled 按 S1 配置返回；2 条不带的 monitorEnabled=null。

### TC-BRS-004 [P0] batchReportStatus — 跨租户 secUid 不污染

**前置**：当前租户 T1 用户登录；故意传 sourceId 属于 T1，但 secUid 对应在另一租户 T2 也存在 anchor_url_user 记录（同 secUid 字符串）。

**期望**：T2 的记录不污染当前查询；monitorEnabled 按 T1 自己的 anchor_url_user（无记录则 null）返回。

### TC-BRS-005 [P0] batchReportStatus — isRemoveRecord=1 不污染

**前置**：当前租户有 secUid=S1 的 anchor_url_user 记录但 `isRemoveRecord=1`（业务已移除）。

**期望**：monitorEnabled=null（被 isRemoveRecord=0 过滤排除）。

### TC-BRS-006 [P0] batchReportStatus — summary 全部是 String 含 JSON

**前置**：3 类报告都 status=2 各 1 条 source。

**期望**：每条 source 的 monitors[] 中：3 个 monitorType 的 `summary` 字段全部是 String（typeof === 'string'），每个 JSON.parse 后字段结构按当前 AI 实际输出。Note：还原度 / 巡检在 B3+ 上线前 status=0，summary=null。

### TC-BRS-007 [P1] batchReportStatus — 100 上限 + 性能

**前置**：100 个 sources 全带 secUid（20 个不同 secUid 重复使用）。

**期望**：HTTP 200，响应 ≤ 2s；SQL log 显示 `tb_anchor_url_user` 仅一次 IN 查询（20 个 secUid），无 N+1。
