# 前端对接 — B9 已读语义改造

> **发布日期**：2026-06-08
> **后端版本**：feature/2.6.01 commit `a2553e8e7`
> **影响范围**：话术质检 / 话术还原度 / 互动巡检 三类报告的"已读"机制
> **协同窗口**：后端 DDL 上线后，前端需在同一迭代内完成本文档变更，避免新旧 UI 错乱

---

## 1. 本次改了什么

### 1.1 业务上

| 旧行为 | 新行为 |
|---|---|
| 录制人/运营/主管手动点"已知晓"按钮，调 `POST /confirmRead` | 录制人**打开报告详情即视为已读**，后端自动写入，前端无需任何操作 |
| 话术质检报告显示三角色「已知晓」勾选 UI（运营/主播/主管） | **整套下线**，不再展示 |
| 互动巡检 / 还原度 报告也有"已读/未读"显式按钮 | **下线**，按钮和确认弹窗全部移除 |

### 1.2 接口上

| 变更类型 | 接口 | 说明 |
|---|---|---|
| **删除** | `POST /replay/script-monitor/confirmRead` | 整个接口下线，前端调用会返回 **HTTP 404** |
| **响应字段变更** | `GET /replay/script-monitor/qualityReportDetail` | 删 `confirmedRecords`、删 `canConfirm`；`isRead` 来源改主表（语义不变） |
| **响应字段变更** | `GET /replay/script-monitor/patrolReportDetail` | 删 `canConfirm`；**新增 `isRead`**；`confirmedAt` 来源改主表（**历史数据重置为 null**） |
| **响应字段变更** | `POST /replay/script-monitor/batchReportStatus` | `monitors[].canConfirm` 删除；`isRead` 来源改主表（语义不变） |
| **响应字段变更** | `POST /replay/script-monitor/reportStatus` | 同上 |

## 2. 前端必做清单（迁移指南）

### 2.1 删除 `confirmRead` 调用

**所有调用点全部移除**。包括：
- 详情页"已读"按钮的点击 handler
- 三角色「已知晓」勾选的提交逻辑
- 任何主动调用 `/confirmRead` 的代码路径

> 新版本部署后调用此接口将 HTTP 404。

### 2.2 移除 UI 元素

- 话术质检报告详情页：**移除"运营已知晓 / 主播已知晓 / 主管已知晓" 三勾选区域**
- 互动巡检报告详情页：**移除"确认已读"按钮**及对应弹窗
- 详情页**不再显示 `canConfirm` 相关 UI**（"我可确认/不可确认"的角色徽章等）

### 2.3 响应字段消费调整

**`qualityReportDetail` 响应**：

```diff
{
  "reportId": "1234567890123456789",
  "isRead": 1,                  // 保留：0=未读 1=已读（语义未变）
- "canConfirm": true,           // 删除字段（已不返回）
- "confirmedRecords": [...],    // 删除字段（已不返回）
  "summaryJson": "...",
  "reportContent": "...",
  ...
}
```

**`patrolReportDetail` 响应**：

```diff
{
  "reportId": "1234567890123456789",
+ "isRead": 1,                  // 新增：0=未读 1=已读（首次查看自动置 1）
- "canConfirm": true,           // 删除字段（已不返回）
  "confirmedAt": "2026-06-08T15:23:00",  // 语义改变（见下）
  ...
}
```

**`batchReportStatus` / `reportStatus` 响应**（数组项 `MonitorTypeStatusVo`）：

```diff
{
  "monitorType": 0,
  "isRead": 0,                  // 保留：来源改主表，语义不变
- "canConfirm": false,          // 删除字段（已不返回）
  ...
}
```

### 2.4 `confirmedAt` 历史数据特别说明（互动巡检）

`patrolReportDetail.confirmedAt` 的**数据语义没变**（仍是首次查看时间戳），但**底层数据源换了**：
- 旧：来自独立表 `tb_script_monitor_read.createDate`
- 新：来自报告主表 `tb_script_monitor_report.confirmed_at`

**历史已读数据不迁移**（产品侧已知悉）。后果：

> 用户上线后第一次进入历史报告时，**所有曾被确认过的报告 `confirmedAt` 都会重置为 `null`**（前端显示为"未查看"），录制人本人再次打开报告时会重新写入当时的时间。

如果前端 UI 上有"于 X 时间已读"这种文案，建议在 `confirmedAt === null` 时显示为"未查看"或不显示时间，**不要回退到"无效时间"等含糊措辞**。

### 2.5 已读判定逻辑变更（重要）

旧：前端拿 `canConfirm + isRead` 决定是否显示"我可以点确认"按钮。
新：**前端不再有"确认"动作**，只是被动展示 `isRead`：

- `isRead === 1` → 在列表/详情上显示"已读"角标
- `isRead === 0` → 显示"未读"角标（红点/数字等）

**不需要前端做任何"判断当前用户能不能写已读"的逻辑**——这是后端职责，前端只读。

## 3. 三类报告变化对比表

| 维度 | 话术质检 (monitorType=0) | 话术还原度 (monitorType=1) | 互动巡检 (monitorType=2) |
|---|---|---|---|
| confirmRead 接口 | 删 | 删 | 删 |
| 角色已知晓三勾选 | **整套删** | 本来就没有 | 本来就没有 |
| `canConfirm` 字段 | 删 | 删（如有） | 删 |
| `isRead` 字段 | 保留（来源改主表） | 保留（来源改主表） | **新增**（来源主表） |
| `confirmedAt` 字段 | — | — | 语义改变（历史数据重置 null） |
| detail 接口写已读 | 录制人查看时自动 | 录制人查看时自动 | 录制人查看时自动 |

## 4. 还有什么不变

- 所有接口路径、HTTP 方法不变（除了 `confirmRead` 整个删）
- 鉴权方式不变（仍是 Header `Authorization: Bearer <jwt>`）
- 报告内容字段（`summaryJson`、`reportContent`、主播信息等）不变
- 错误码不变
- 分页、过滤等查询参数不变

---

## 5. 前端可自测的行为

部署后前端可以这样自测：

1. **录制人打开报告详情**：
   - 第一次打开 → 响应 `isRead === 1`（后端写入了）
   - 列表刷新 → 该报告显示"已读"
2. **同租户非录制人打开报告详情**：
   - 响应 `isRead` 保持 0（不会写入）
   - 列表上仍显示"未读"
3. **调用已删除的 confirmRead 接口**：
   - HTTP 404
4. **触发 `triggerReport` 重新生成报告**：
   - 完成后 `isRead === 0`、`confirmedAt === null`（重置）
