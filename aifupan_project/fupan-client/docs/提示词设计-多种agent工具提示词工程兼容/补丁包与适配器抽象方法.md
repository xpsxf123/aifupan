# 补丁包与适配器抽象方法（多 Agent 通用）

本文件把本项目在 Claude Code 上验证通过的兼容方式抽象成“通用方法”，用于迁移到任何 Agent 开发工具。

目标：你只维护一套提示词工程单一来源目录，任何工具都通过“适配器（adapter）”访问同一套资料。

---

## 1. 统一术语

### 1.1 单一来源（Canonical Source）

只允许存在一份长期维护的提示词工程目录，例如：

- `agnet/`（本项目）
- `agent/`
- `.agent/`

单一来源内应包含：

- `BOOTSTRAP.md`（统一入口导航）
- `AGENT.md / TOOLS.md / MEMORY.md / INDEX.md`
- `CHANGE_LOG.md / POLICIES.md`
- `wiki/`、`skills/`、`self_skills/`

### 1.2 适配器（Adapter）

适配器是“工具发现层”的一组文件/配置，用于把某个工具的默认加载链路引导回单一来源。

适配器必须满足：

- 不承载长期业务知识
- 可以有多个入口文件（根入口、工具目录入口、子目录入口），但最终必须统一回到 `BOOTSTRAP`

### 1.3 入口桥（Entry Bridge）

入口桥是适配器的一部分，用于解决“工具只读取某些固定文件名”的问题。

入口桥分两类：

- **简短根入口**：放最关键的规则内联 + 下一跳指引
- **工具目录详细入口**（若支持）：放完整执行约束、读链路、文档维护规则

### 1.4 自动化兜底（Hooks / Automation）

用于把“模型自觉”变成“确定性行为”：

- `SessionStart`：启动/恢复/压缩后重新注入基础治理摘要
- `PostToolUse`：写文件成功后做文档维护检查提醒

---

## 2. 通用兼容方案（固定四层）

任何工具适配都必须落到这四层（概念不可省略）：

1. **单一来源层**：真实规则、技能、记忆、wiki 的唯一存放处
2. **统一引导层**：`BOOTSTRAP.md`，定义读取顺序与任务场景链路
3. **工具桥接层**：入口文件、规则目录、工具约定的发现机制
4. **自动化兜底层**：hooks 或等价机制（SessionStart / PostToolUse）

---

## 3. 适配器实现步骤（让 Agent 自己“读规则 → 造适配器”）

当你把补丁包放进一个新项目后，你可以只对目标 Agent 说一句：

> 先自检你会自动读取哪些入口文件/目录/是否支持 hooks；然后按补丁包的方法实现适配器，把你的默认加载链路桥接到单一来源 BOOTSTRAP。

### 3.1 必须先做“入口读取规则自检”

让目标 Agent 输出一张表：

- 会读哪些入口文件（根目录？工具目录？子目录？）
- 会读规则目录吗？
- 支持 hooks 吗？有哪些事件点？
- 支持 import/include 吗？

没有这张表，不允许直接写适配器。

### 3.2 入口桥写法（通用要求）

入口桥必须做到：

- **内联少量关键规则**（禁止只写路径映射）
- **明确下一跳**（必须继续读取哪个文件）
- **明确冲突优先级**（单一来源优先）

### 3.3 hooks 写法（通用要求）

若工具支持 hooks，则必须实现：

- `SessionStart`：注入“单一来源 + 必读文件 + 技能优先级 + 知识漏斗”的短摘要
- `PostToolUse`：当修改治理文件（单一来源、适配器、兼容文档）时，提示补维护 `CHANGE_LOG / POLICIES / 兼容文档`

注意：hooks 注入内容必须短、稳定、可跨终端编码。

---

## 4. 补丁包（Patch Pack）推荐交付物

建议每个项目都携带一个“补丁包目录”（仅文档/模板，不绑定具体工具）：

- `patch/agent-bridge.manifest.sample.json`
  - 定义单一来源目录、BOOTSTRAP 路径、核心必读文件列表、适配器能力声明
- `patch/adapter-checklist.md`
  - 适配器落地检查表（入口、规则目录、hooks、写回）
- `patch/README.md`
  - 复制到新项目后的使用方式

---

## 5. 维护与治理

当你修改以下内容时，必须更新单一来源的治理记录：

- 单一来源规则（AGENT/TOOLS/MEMORY/INDEX/BOOTSTRAP）
- 适配器入口桥文件
- 规则目录
- hooks
- 兼容设计文档

需要更新的文件：

- `CHANGE_LOG.md`：记录“规则/技能/索引/桥接机制”的变更
- `POLICIES.md`：记录“可复用策略与经验”

---

## 6. 验收问题（跨工具一致）

适配完成后，让目标 Agent 自检回答：

1. 单一来源目录在哪里？
2. 你会自动读取哪些入口文件？按什么顺序？
3. 读到入口后下一跳是什么？是否会继续读到 `BOOTSTRAP`？
4. hooks 是否存在？SessionStart 会注入什么？PostToolUse 会检查什么？
5. 若我修改了规则/桥接机制，你会提醒我维护哪些文档？

以上问题稳定可回答，才说明“多工具共用一套提示词工程”的兼容补丁真正落地。
