# Adapter Checklist（跨工具通用）

> 目标：让任意 Agent 工具在“只自动读入口文件”的情况下，也能稳定进入提示词工程单一来源继续读取，并且在改动治理文件后不会漏维护文档。

## A. 入口读取规则自检（必须先做）

- [ ] 工具会自动读取哪些入口文件？（根 / 工具目录 / 子目录）
- [ ] 工具是否会读取规则目录？目录名规则是什么？
- [ ] 工具是否支持 hooks？支持哪些事件点？（SessionStart/PostToolUse 等）
- [ ] 工具是否支持入口文件 include/import？

没有这四个答案，不允许开始写适配器。

## B. 单一来源（Canonical）检查

- [ ] 项目只有一套提示词工程单一来源目录（例如 `agnet/`）
- [ ] 单一来源包含 `BOOTSTRAP.md`
- [ ] 单一来源包含核心治理文件：`AGENT/TOOLS/MEMORY/INDEX/CHANGE_LOG/POLICIES`
- [ ] wiki/skills/self_skills 在单一来源目录内

## C. 入口桥（Entry Bridge）要求

- [ ] 入口桥包含“单一来源是谁”的明确声明
- [ ] 入口桥包含“下一跳必须读 BOOTSTRAP”的强制语句（MUST）
- [ ] 入口桥**内联少量关键规则**（禁止只写路径映射）
- [ ] 若工具支持多入口，采用：
  - 根入口：简短摘要 + 关键规则内联
  - 工具目录入口：详细配置 + 强制继续读取

## D. 规则目录（Rules Dir）要求（若工具支持）

- [ ] 将高优先级规则拆分为短文件：
  - 核心治理
  - 上下文漏斗（索引->域->细节）
  - 写回与变更记录（WAL/CHANGE_LOG/POLICIES）
  - 多 Agent 兼容边界

## E. hooks（若工具支持）

- [ ] SessionStart：启动/恢复/清理/压缩时注入基础治理摘要
- [ ] PostToolUse：写文件成功后做文档维护检查提醒
- [ ] hooks 注入内容必须短、稳定、跨终端编码可读

## F. 治理写回

- [ ] 规则/技能/索引/桥接机制变更 → 更新 `CHANGE_LOG`
- [ ] 可复用策略沉淀 → 更新 `POLICIES`
- [ ] 可复用知识沉淀 → 写入对应域 `wal/`，再按窗口合并到域 `index.md`

## G. 验收问题（必须能稳定回答）

- [ ] 单一来源目录在哪里？
- [ ] 你会自动读取哪些入口文件？顺序是什么？
- [ ] 读到入口后下一跳是什么？是否会继续读到 `BOOTSTRAP`？
- [ ] hooks 是否存在？分别做什么？
- [ ] 修改治理文件后，你会提醒我维护哪些文档？
