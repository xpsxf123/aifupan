# 提示词设计

> 本目录基于 `c:\Users\JYJY\Desktop\fupan-client\agent` 的当前真实内容抽取而成，目标是把本项目已经落地的提示词工程、知识治理、技能体系、扩展方式与迁移方法，整理为一套可直接复用到其他项目的开发说明文档。

## 文档目标

- 提炼本项目提示词工程的核心设计，不停留在“写了哪些 prompt”，而是解释“为什么这样设计、各层怎么协同、如何长期维护”。
- 将当前项目中的通用能力与项目绑定能力分层抽取，明确哪些可以直接复用，哪些需要按业务重新定制。
- 形成一套适合新项目初始化、老项目治理升级、多人协作沉淀的工程说明。
- 保留与当前 `agent/` 目录的一一映射关系，方便后续继续追溯和更新。

## 适用范围

- 需要在项目仓库内建设提示词工程、智能体规则、知识库与技能体系的团队。
- 希望将“对话经验”沉淀为“仓库资产”的研发团队。
- 需要解决上下文膨胀、规则漂移、多人协作冲突、知识不可检索、技能不可发现等问题的项目。
- 需要把智能体工程做成可升级、可迁移、可审计资产的私有化或长期维护项目。

## 提炼后的总结构

这套提示词工程不是单一提示词文件，而是一个由以下层次组成的“工程化系统”：

- 角色与规则层：定义身份、职责、交付物、强规则、边界与优先级。
- 图谱与导航层：定义从哪里进入知识、如何最小加载上下文。
- 知识内容层：把高价值细节下沉到 wiki 域文档，避免总索引膨胀。
- 写回与增量层：通过 WAL 先写后并，降低多人协作冲突。
- 长期记忆层：只保留高频、稳定、可复用结论。
- 技能执行层：将重复性工作抽象为可组合、可审计的技能。
- 治理与演化层：通过策略、反思、变更日志、脚本与版本机制持续迭代。
