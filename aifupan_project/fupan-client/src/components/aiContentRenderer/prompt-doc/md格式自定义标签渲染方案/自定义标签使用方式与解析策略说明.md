# Markdown 指令式自定义标签：使用方式与解析策略说明（方案草案）

## 一、推荐写法（给模型/提示词）

### 1.1 容器（双标签/块）

推荐使用“开始指令 + Markdown 内容块 + 结束指令”：

```text
[!##]{element="card"}
### 核心结论
- 结论 1
- 结论 2
[##!]
```

### 1.2 意图声明（单标签）

推荐使用“单标签 + 紧随其后的 Markdown 数据块”：

```text
[!##!]{element="echarts-pie",title="年龄分布"}
| 年龄段 | 占比 |
|---|---|
| 18-23 | 18.06 |
| 24-30 | 29.34 |
```

### 1.3 数据块（结构化 JSON）

推荐把 JSON 放在“数据块容器”内，避免污染正文：

~~~text
[!##]{element="data-block",type="structured",visible=false,cacheKey="quota"}
```json
{ "limit": 10, "used": 3 }
```
[##!]
~~~

说明：

- `visible=false`：页面不显示该块，但前端可缓存并供函数读取。
- `visible=true`：将该 JSON 交给对应 type 的渲染器输出可视化/结构化卡片。

补充约束：

- 当 `visible=false` 时：允许不传 `type`
- 当 `visible=true` 时：建议传 `type`；不传则默认按 `structured` 处理

## 二、解析总流程（渲染器侧）

推荐的渲染管线（与旧 aifupan 标签方案保持一致的理念）：

1. **指令预解析**：扫描文本中“行首”的 `[!##]` / `[!##!]` / `[##!]`，构建指令 Token 流。
2. **构建结构树**：把开始/结束标签配对，形成 Block AST；单标签形成 Self AST。
3. **数据提取**：对 `data-block` 等“数据型 element”先提取 JSON，并按 `visible/cacheKey` 做缓存决策。
4. **占位替换**：把 AST 转换为 HTML 占位符（或短 token），并把原始 Markdown 正文保留下来。
5. **Markdown 渲染**：对剩余 Markdown 做标准渲染（markdown-it）。
6. **回填渲染**：用 element/type 对应的 renderer 生成 HTML，替换占位符。
7. **纯 Markdown 模式**：若走 pureMd，需移除所有指令与数据块（按策略决定是否保留/过滤 data-block）。

## 三、关键策略（避免误匹配）

### 3.1 行首约束

仅当以下条件满足才识别为指令：

- 指令出现在行首（允许前置空格）。
- 指令完整闭合在同一行。

这样可减少正文中出现 `[!##]` 字符串时被误判的概率。

### 3.2 转义约定

若需要输出字面量 `[!##]`，建议：

- 将其放入 Markdown code block / inline code；
- 或者在 `[` 前加反斜杠：`\[!##]`（渲染器侧可选择识别并忽略被转义的指令）。

## 四、与旧方案混用（过渡期）

建议渲染器支持：

- 旧 `<aifupan-...>` 标签
- 新 `[!##]...` 指令

并提供统一的“element/type”抽象层，保证渲染能力可持续扩展。
