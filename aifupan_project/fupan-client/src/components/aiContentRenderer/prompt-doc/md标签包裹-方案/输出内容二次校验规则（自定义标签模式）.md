# 扩展 Markdown 输出二次校验规则

## 一、适用范围

本校验规则用于验证 AI 模型输出的扩展 Markdown 内容（含 `aifupan-` 自定义标签）是否符合规范，确保前端渲染引擎能够正确解析。

## 二、标签语法校验

### 2.1 基本格式检查

- 所有自定义标签必须符合 XML 风格：
  - 单标签：`<aifupan-组件类型-参数 />`（注意末尾空格和斜杠）
  - 双标签：`<aifupan-组件类型> ... </aifupan-组件类型>`
- 标签名称必须以 `aifupan-` 开头，后续为小写字母、数字和连字符。
- 属性格式为 `key="value"`，属性值用双引号包裹。

### 2.2 组件类型白名单

允许的组件基础类型包括：
- `theme-aurora`、`theme-business`、`theme-warm`
- `skin-glass`、`skin-paper`、`skin-minimal`
- `title`、`title-1` 至 `title-6`、`title-*-filled`、`title-*-bordered`、`title-*-leftbar`、`title-*-underline`
- `highlight`、`mark-red`、`badge`、`callout`、`note`、`spoiler`、`kbd`
- `card`、`card-hover`、`card-head`、`card-body`、`quote-modern`、`columns-2`、`column`
- `list-check`、`list-steps`、`list-icon`
- `table-striped`、`table-bordered`、`table-compact`、`table-hover`
- `echarts-line`、`echarts-bar`、`echarts-pie`、`echarts-area`、`echarts-scatter`、`echarts-radar`
- `progress`、`statistic`、`statistic-trend`、`meter`
- `mermaid`、`flowchart`
- `timeline`、`steps`
- `code`、`code-diff`
- `tabs`、`accordion`、`divider`、`tooltip`、`emoji`
- `data-block`

任何不在白名单内的标签将被标记为警告。

### 2.3 嵌套规则检查

- 默认情况下，`aifupan-` 标签内部不应继续出现新的 `aifupan-` 标签。
- 以下受控组合允许嵌套：
  - `aifupan-card` 内允许 `aifupan-card-head`、`aifupan-card-body`
  - `aifupan-columns-*` 内允许 `aifupan-column`
- 若出现未在白名单中的嵌套关系，校验器报错。
- 标签闭合必须匹配，无交叉嵌套。

### 2.4 内容格式校验

- 图表标签（`echarts-*`）内部必须包含一个标准 Markdown 表格，且表格至少有一行表头及一行数据。
- 若 `echarts-*` 使用单标签形式，则其后紧随的数据块必须是标准 Markdown 表格。
- `progress` 统一建议使用 `value` 属性，取值必须在 `0-100` 之间。
- `aifupan-mermaid` 内部应优先包含标准 Markdown fenced code block，语言名必须为 `mermaid`。
- Mermaid fenced code block 内允许出现标准 Mermaid 流程语法，不应混入其他无关 Markdown 段落。
- `aifupan-echarts-pie` 外层不建议再嵌套 `aifupan-column`；若出现该结构，给出“图表嵌套层级过深”警告。
- `font` 标签的 `color/bgColor` 仅允许颜色名、十六进制颜色或 `rgb/rgba` 值。
- `theme-*` 与 `skin-*` 标签建议只在文档开头出现一次；若出现多个，以第一个为准或给出警告。
- 若 `title` 标签后或内部包含 Markdown 标题（`# / ## / ###`），应以 Markdown 标题级别为准，自定义标签只负责样式增强。
- `card` 若同时存在 `title` 属性和 `card-head`，优先使用 `card-head`，并给出“标题定义重复”的警告。
- `columns-*` 若同时存在 `column` 子标签与 `---` 分隔，优先使用 `column`，并给出“分栏定义重复”的警告。
- `data-block` 必须为双标签形式；内部 JSON 推荐使用 ` ```json ` fenced code block（更稳定），但若提示词要求“严格 JSON（不允许 ```json）”，也允许直接输出纯 JSON（前端同样支持解析）。若 `visible="false"`，渲染器应过滤掉可见内容但保留缓存。
- `data-block` 当 `visible="true"` 时建议提供 `type`（用于选择 JSON 解析渲染逻辑）；若不提供则默认按 `structured` 处理；若 type 未识别，给出 warning 并降级为不渲染（可选仅缓存或直接移除）。

- `data-block` 的各 `type` 详细 JSON 字段约定与示例见：[data-block/README.md](file:///c:/Users/JYJY/Desktop/fupan-client/src/components/aiContentRenderer/prompt-doc/data-block/README.md)。

## 三、语义合理性检查

- 若 `progress` 的 `value` 超出范围，自动钳位。
- 图表表格中数值列应可解析为数字，若含非数字字符（如单位），发出警告。
- 标签属性值若包含非法字符（如未转义的双引号），提示修正。
- `list-icon` 的 `icon` 建议使用语义值，如 `check`、`warning`、`info`、`star`、`arrow`、`close`，不要输出未定义 iconfont 名称。
- `steps` 若存在 `步骤1/步骤2/步骤3` 这类顶层步骤标题，则其后的普通说明行应归属于当前步骤，不应继续拆成新的步骤。
- `steps` 若使用 `aifupan-steps-item` 或 `aifupan-steps-数字` 标记，则必须以这些标记作为步骤边界。
- `statistic` 的 `value` 若不包含数字、百分比、金额或数量单位，发出“语义不匹配”警告，建议改用 `card` / `callout`。
- `statistic-trend` 若只传纯文字结论（如“偏低”“良好”“较差”）且无明确 `trend` / `positive` / `negative`，发出“趋势定义不完整”警告。
- Mermaid 判断节点必须使用 `{}` 表达，例如 `C{用户犹豫}`；若判断语义被写成普通节点，发出“判断节点语义不清晰”警告。
- Mermaid 判断节点若存在多条外连边，则应作为分支节点处理；若解析后无法形成清晰分支关系，发出“流程分支结构异常”警告。
- 业务漏斗或流程若使用 `mermaid` 但未采用 fenced code block，发出“Mermaid 代码块格式不标准”警告，并建议自动修正。
- 若文本块在生成后仍残留明显 Markdown 语法（如 `**`、`###`、`- `、`1.`），发出“Markdown 未完成解析”警告。
- 若图表使用 `echarts-pie` 却未提供“名称列 + 数值列”的两列表结构，直接判定为无效。
- 若同时声明多个冲突主题（如 `theme-business` 与 `theme-warm`），发出警告。
- 若未声明主题和皮肤，不视为错误，前端可自动匹配。
- 若 `card` 外部与 `card-head` 表达同一标题内容，提示“标题重复”警告，建议将标题并入 `card-head`。

## 四、自动修正策略

校验器在可能的情况下应自动修正：
- 补全遗漏的闭合标签。
- 修正未转义的属性引号。
- 将过大的进度数值截断至 100。
- 当 `card` 已使用 `card-head` 时，移除冗余 `title` 属性。
- 当 `list-icon` 使用不可识别图标值时，自动回退为默认可见符号。
- 当 `steps` 缺少明确的步骤标题边界时，建议回退为普通列表渲染。

若无法自动修正，返回 `valid: false` 并附带错误详情。

## 五、校验输出格式

校验完成后返回：

{
  "valid": true/false,
  "errors": [ "错误信息" ],
  "warnings": [ "警告信息" ],
  "correctedText": "修正后的文本（若无修正则为原文本）"
}

## 六、使用建议

此校验器可部署于 API 网关或前端解析前，确保渲染器接收到的内容符合预期。

## 七、推荐提示词枚举

为了让模型稳定输出主题化内容，建议在提示词中明确指定以下枚举值：

### 7.1 Theme Enum

- `aurora`
- `business`
- `warm`

### 7.2 Skin Enum

- `glass`
- `paper`
- `minimal`

### 7.3 推荐组合

- `business + paper`：复盘、报告、周报、经营分析
- `aurora + glass`：技术方案、系统设计、监控面板、代码说明
- `warm + glass`：活动总结、海报展示、亮点内容
- `business + minimal`：规则说明、规范文档、接口说明
