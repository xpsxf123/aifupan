# 规格质量检查单

## 技能目的
- 在动手改代码前，把不明确/不可验收/缺依赖的问题暴露出来
- 把“待确认项”集中管理，避免在实现阶段反复返工
- 输出可复用的验收检查单，便于测试/评审复用

## 输入参数
- `spec_text`：必填，文本。PRD/需求描述/方案文档/对话摘要
- `scope`：选填，枚举。`frontend` | `agent_docs` | `mixed`（默认 `frontend`）
- `existing_constraints`：选填，列表。已知规则（目录约束、命名、禁用行为）

## 输出
- `quality_report`：质量报告（通过/警告/阻塞）
- `blocking_issues`：阻塞问题列表（必须澄清才能实现）
- `non_blocking_issues`：非阻塞问题（可边做边确认）
- `acceptance_checklist`：验收清单（按页面/接口/交互/异常分组）

## 检查维度（推荐）
- 目标是否可验收：是否有明确的“完成定义”
- 范围边界是否清晰：哪些不做、哪些不改、哪些仅做开关接入
- 依赖是否齐全：接口文档/字段/枚举/权限点/路由入口是否明确
- 异常与降级：接口失败、空数据、权限不足、加载态是否定义
- 兼容性：是否影响既有页面/路由/菜单/状态共享
- 安全与隐私：是否涉及 Token/用户数据展示/日志敏感信息

## 适用场景
- 新功能上线前的“方案审查”
- 接口契约不确定、字段易变、权限点复杂的需求
- 任何需要输出可复用“验收自检清单”的交付

## 边界
- 不替代产品/后端给出最终契约；只输出缺口与澄清点
- 不在未确认的前提下写死关键字段/枚举
