# 老项目Wiki逆向引导器

## 技能目的
- 面向“已有代码但缺少体系化文档”的老项目，逆向建立 wiki + INDEX 知识图谱
- 同步生成 MEMORY.md 的长期摘要，形成可持续的知识沉淀入口
- 输出“缺口清单”，指导后续把不完整处补齐为可验收标准

## 输入参数
- `project_assets`：必填，列表/文本。可用资产（代码目录、路由、接口定义、测试用例、README、PRD等）
- `focus_scope`：选填，枚举。`frontend` | `backend` | `test` | `ops` | `product` | `full`，默认 `full`
- `constraints`：选填，文本。项目硬约束（安全红线/环境/依赖/发布流程）

## 输出
- `index_seed`：初版 INDEX.md（实体清单 + 关键关系 + 权重建议）
- `wiki_seed_plan`：初版 wiki 页面列表（每页写作要点与引用来源）
- `memory_seed`：MEMORY.md 初版摘要（稳定约束/高频结论/模板入口）
- `gap_list`：缺口清单（缺文档/缺契约/缺验收/命名不一致/权限不清等）
- `bootstrap_steps`：建议的补齐顺序与最小可用里程碑

## 逆向步骤（推荐）
1. 入口盘点：路由/菜单/页面目录/请求封装/状态管理/权限拦截/构建与环境
2. 实体抽取：模块/页面/接口/数据模型/错误码/权限/验收标准/运行手册
3. 关系归纳：contains / depends_on / implements / validates / conflicts_with
4. 生成 INDEX：只放路由关系与权重，便于后续检索定位
5. 生成 wiki：为高权重实体创建内容页骨架（定义/适用范围/示例/相关链接）
6. 生成 MEMORY：提炼稳定约束与复用入口，避免写入一次性细节
7. 输出缺口：把无法从资产中确定的信息标注为“待确认/待补齐”

## 写回目标
- `INDEX.md`：初版图谱索引
- `wiki/`：初版内容层页面（骨架优先）
- `MEMORY.md`：初版长期摘要
- `DREAMS.md` / `POLICIES.md`：沉淀逆向过程中的策略与常见坑（可选）

## 边界
- 逆向推断必须标注证据来源；缺证据的内容只能进入缺口清单
- 不自动修改工程代码；默认只产出文档与建议
