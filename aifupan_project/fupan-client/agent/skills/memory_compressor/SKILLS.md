# 记忆压缩器

## 技能目的
- 把“高频复用、长期稳定”的信息压缩到 MEMORY.md，降低重复沟通成本
- 避免把细节、临时决策写成长期记忆
- 与 wiki/INDEX 协同：细节进 wiki，路由进 INDEX，长期摘要进 MEMORY

## 输入参数
- `source_material`：必填，文本。本次对话/交付物/结论/约束/踩坑与修复
- `memory_targets`：选填，列表。默认：`MEMORY.md`（必要时补充 wiki 页面）
- `evidence`：选填，列表。来源锚点（文件名/模块名/接口名/约定名）

## 输出
- `memory_patch`：可直接写入 MEMORY.md 的摘要条目（按既有“摘要结构”组织）
- `demote_list`：不应进入长期记忆的信息清单（原因：一次性/不稳定/缺证据）
- `followup_writeback`：需要同步写入 wiki/INDEX/DREAMS/POLICIES/CHANGE_LOG 的建议

## 压缩规则
- 只保留稳定事实：技术栈/安全红线/接口鉴权/命名约定/复用模板入口/高频结论
- 去细节保结构：把具体步骤/大段说明下沉到 wiki
- 保留证据：每条摘要至少给出一个“来源线索”便于回溯
- 控制粒度：一条摘要解决一个可复用问题，避免“杂项大段”

## 工作步骤（推荐）
1. 分类：用户偏好 / 项目约束 / 高频结论 / 模板入口
2. 去噪：剔除一次性任务细节与临时状态
3. 合并：合并重复与同义摘要，保留最新且稳定的表述
4. 生成补丁：产出 MEMORY.md 可落盘条目
5. 联动写回：需要时同步 wiki/INDEX，并记录策略/变更

## 写回目标
- `MEMORY.md`：长期记忆摘要（主）
- `wiki/<topic>.md`：细节沉淀（可选）
- `INDEX.md`：路由关系更新（可选）
- `DREAMS.md` / `POLICIES.md` / `CHANGE_LOG.md`：反思/策略/变更（按需）

## 边界
- 不把敏感信息（密钥/Token/个人隐私）写入任何记忆文件
- 无证据或不确定的信息只能进入“待确认清单”，不得固化为长期记忆
