# 项目-复盘客户端-请求与接口体系

## 本文档用途

- 统一说明：项目内存在两套请求域（back/client），它们的 baseURL、签名、错误处理、loading 行为分别是什么。
- 给接口对接提供“调用侧规范”：该用哪个对象、怎么传 option、哪些 code 会触发特殊逻辑。

## 定义：三套调用入口

### 1) $httpBack（业务后端 API 聚合）

- 入口：`this.$httpBack`
- 聚合定义：`src/utils/request-api-back.js`
- 传输层：`src/utils/request-back.js`
- baseURL：`window.SITE_CONFIG.backApiURL`

适用：

- 与远端业务后端交互（需要 Token/source/签名）

#### 直播间授权状态统一查询（强约定）

- 统一入口函数：`src/utils/liveRoomAuthStatus.js`
- 使用方式：`getLiveRoomAuthStatus(secUid)`
- 目标：后续所有“巨量/千川/视频号/来客等平台授权状态”的读取，都只通过该工程函数获取；页面侧先逐步替换，避免在业务组件内散落授权状态查询实现

### 2) $httpClient（本地客户端 API 聚合）

- 入口：`this.$httpClient`
- 聚合定义：`src/utils/request-api-client.js`
- 传输层：`src/utils/request-client.js`
- baseURL：`window.SITE_CONFIG.clientApiURL`（并可能被 UA port 覆盖）

适用：

- 与桌面端（C#）或本地服务交互（例如设置、录制、授权等）
- 注意：Web 环境下会直接 reject（属于设计限制）

### 3) $httpBack2 / $httmlBack2（可注入 baseURL 的扩展请求）

- 入口：`this.$httpBack2`、`this.$httmlBack2`
- 定义：`src/utils/request-back2.js`
- 目标：在不破坏 `$httpBack` 的情况下，提供“调用时注入 baseURL”或“创建指定 baseURL 的 client”能力

适用：

- 临时接第三方域、或需要与 back 不同的域名交互

## 返回结构与成功/失败判断

两套请求层都遵循相同的成功判断：

- HTTP：`res.status === 200`
- 业务码：`res.data.code === 0`

失败时会 `Promise.reject(res.data)`，调用侧应在 `.catch` 或 `try/catch` 中处理。

## back 请求层（request-back.js）关键约定

### 请求头注入

- `Token`：来自 `store.state.token`
- `source`：平台来源
- 签名头：由 `src/utils/signature.js` 生成

### option 约定（调用侧）

大多数 `get/post/put/del` 都支持额外 option：

- `load`：是否显示 loading（默认 true）
- `notFormat`：是否跳过参数格式化
- `config`：透传/覆盖 axios config（headers/responseType 等）
- `baseURL`：单次覆盖 baseURL

### 错误处理

- `code === 4001`：视为登录失效，清理登录信息并跳转登录（白名单路由可能只 reject 不跳转）
- iframe 场景：会通过 `postMessage` 回传给父页面，并在 iframe 情况下直接 reject

## client 请求层（request-client.js）关键约定

### baseURL 动态覆盖（端口）

会尝试从 `navigator.userAgent` 解析 `port=xxxx`，把 baseURL 覆盖为：

- `http://127.0.0.1:${port}/api`

### Web 环境禁用

若为 Web 环境，会直接 `Promise.reject()`，避免在网页端误调用本地能力。

### 错误处理

- `code === 4001`：清登录并跳登录
- `code === 5601`：触发 `store.commit('setTimeAccurate')`
- `code === 7001`：不弹错误提示（把错误文本置空）

## loading 机制（两套类似）

- 通过 `httpLoading` 对“每个 url 的 loading 状态”做锁控制
- 支持用 `sessionStorage.notLoading` 全局禁用 loading
- 存在 `localStorage.notCloseLoading` 时，关闭 loading 会被抑制

## API 聚合层的“内部落 store”约定

部分 API 会在聚合层内部直接 commit（调用侧无需额外写入 store），典型：

- userProperty 相关：拉取后 commit `saveUserproperty`

建议：

- 页面侧调用前先确认：该接口是否已经在聚合层里写入 store，避免重复写入造成状态污染。
