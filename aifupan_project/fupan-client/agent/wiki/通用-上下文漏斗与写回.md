# 通用-上下文漏斗与写回

本页提炼“上下文获取与写回”的通用策略，目标是：减少猜测、减少无关加载、降低多人协作冲突。

## 正向漏斗（读上下文）
1. 从 `INDEX.md` 与 `wiki/KNOWLEDGE_GRAPH.md` 进入域 `index.md`
2. 只加载本次任务涉及的域（api/router/state/components/preferences/specs）
3. 读取最小必要页面后再开始实现，避免全量扫描

## 反向漏斗（写回知识）
1. 先写 WAL：把新增知识写到对应域的 `wiki/<domain>/wal/`（append-only）
2. 再合并：在合适窗口将 WAL 合并到 `wiki/<domain>/index.md`
3. 最后固化：高频稳定结论才进入 `MEMORY.md`

## 适用场景
- 需求涉及多个模块/页面联动
- 接口契约变动频繁，需要可回溯记录
- 多人同时维护 wiki/skills，担心冲突与膨胀
