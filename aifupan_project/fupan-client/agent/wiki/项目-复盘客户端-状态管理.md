# 项目-复盘客户端-状态管理

## 本文档用途

- 统一说明：项目的 Vuex store 放在哪里、持久化哪些字段、哪些 API 会“内部落 store”。
- 给后续新增状态/排查状态丢失提供定位路径。

## store 入口

- 文件：`src/store/index.js`
- 使用：在 `src/main.js` 中注入到根 Vue 实例

## 持久化策略

项目使用 `vuex-persistedstate` 做持久化：

- 存储 key：`replayVuex`
- 仅持久化特定字段（白名单）：
  - `userInfo`
  - `token`
  - `replayPageMenu`
  - `homeMenu`
  - `detectionStatus`
  - `startDetectionTime`
  - `versionType`

这意味着：

- 未在白名单内的 state，刷新后会丢失
- 新增需要跨刷新保留的状态时，应评估是否要加入白名单

## 典型数据写入点

### 登录/退出

- 登录成功后，通过 mutation 写入：
  - `token / userInfo / versionType`
- 清理登录信息：`clearLoginInfo()` 会清空上述字段并影响动态路由标识

### initApp 阶段

- 若 UA 命中 `aifupan`，会调用 client 接口获取机器码并写入 store

### API 聚合层内部 commit

部分接口在 API 聚合层内部直接 commit（调用侧无需额外写入），典型：

- userProperty 信息（`saveUserproperty`）

## getter 的隐式初始化注意点

项目存在“读取 getter 时触发异步初始化”的约定（例如 `getVersionType` 会 dispatch 初始化），调用侧应注意：

- getter 的读操作可能导致副作用（触发接口/异步）
- 在组件 created/mounted 频繁读取时，避免造成重复初始化
