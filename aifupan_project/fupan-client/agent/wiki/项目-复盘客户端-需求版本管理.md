# 项目-复盘客户端-需求版本管理

## 定义

需求版本管理指把每个产品版本对应的需求（PRD/补充材料/整合版）登记成固定入口，并在开发、联调、验收时始终以该入口为准。

## 适用范围

- 复盘客户端（fupan-client）前端需求实现与回归
- 服务端/管理后台同步发布的跨端能力（以版本为边界对齐入口可见性）

## 入口与约束

- ~~需求版本库入口：`docs/需求版本库/README.md`~~（已归档，相关关键信息已蒸馏到 MEMORY.md 与 wiki）
- 单版本需求入口优先级：
  - 主PRD（如有，按项目实际文档路径）
  - 整合版（补齐流程/交互/文案与冲突点列表）
  - 原始需求抽取（仅辅助定位原始口径，不直接作为实现准绳）

## 使用流程

1) 实现前：先在对应项目的需求文档中定位目标版本目录，再进入该版本的 PRD 与整合版。
2) 开发中：以 PRD 的 Requirements/Acceptance 为准，整合版仅用于补齐流程细节与文案示例。
3) 评审/验收：以 PRD 的验收项（Acceptance Checklist）为准；若发现冲突，将冲突追加到整合版"待确认事项"，并同步给产品/测试。
4) 复用：后续同类版本只在对应位置登记新增行，避免重复"到处找文档入口"。
