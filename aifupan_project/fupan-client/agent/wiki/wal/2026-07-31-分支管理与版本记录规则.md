# 2026-07-31 分支管理与版本记录规则

## 摘要

引入「版本开发目录」与「版本功能明细」体系，解决 `dev-*` / `test-*` / `reslease-*` 多分支并行开发时的变更追踪难题。

## 分支命名规范

| 前缀 | 用途 | 示例 |
|------|------|------|
| `dev-` | 功能开发微分支 | `dev-2.6.2.1` |
| `test-` | 测试集成分支 | `test-2.6.2` |
| `reslease-` | 预发布/候选分支 | `reslease-2.6.2` |

## 目录结构

- `docs/版本开发目录/X.Y.Z.md`：记录 `dev-X.Y.Z.W` 微分支的功能名称、变更时间、变更文件、功能描述、合并状态
- `docs/版本变更/X.Y.Z.md`：记录 `test-X.Y.Z` / `reslease-X.Y.Z` 的「变更明细」表格 + 「版本功能明细」表格

## AI 行为规则摘要

### dev-X.Y.Z.W 分支
1. 检查 `docs/版本开发目录/X.Y.Z.md` 是否存在，不存在则创建
2. 检查当前功能分支是否已记录，未记录则追加空模板
3. 每次提交时更新变更文件列表和功能描述
4. 执行任务前检测同一大版本下其他 dev 分支是否修改相同文件（重复分支冲突检测），`aiDev-*` 不触发

### test-X.Y.Z / reslease-X.Y.Z 分支
- 提交代码时更新 `docs/版本变更/X.Y.Z.md` 的「变更明细」表格
- 合并 dev 分支时自动从开发目录读取功能描述，写入「变更明细」和「版本功能明细」

### aiDev-* 分支
- 不做任何自动记录操作，不触发重复分支检测

## 版本功能明细说明

位于 `docs/版本变更/X.Y.Z.md` 的「变更明细」表格之后，用于列出当前版本完整功能清单，供测试团队作为测试验收清单。功能新增/移除/增强时同步维护。
