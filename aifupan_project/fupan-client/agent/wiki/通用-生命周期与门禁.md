# 通用-生命周期与门禁

本页定义“从分析到交付”的推荐生命周期，以及在关键节点引入门禁（quality gates）的原则。

## 生命周期（推荐）
1. Clarify：澄清目标与范围，产出 Focus Card
2. Explore：最小必要上下文加载（按域漏斗）
3. Propose：产出方案与任务拆解（可验收/可回滚）
4. Implement：增量修改，避免大范围重构
5. Verify：关键路径自检（构建/运行/基本诊断）
6. Writeback：WAL / wiki / INDEX / CHANGE_LOG 写回

## 门禁（推荐）
- Ambiguity Gate：需求不清晰时阻塞推进，只输出待确认项
- Scope Guard：超出 Focus Card 的路径/范围时阻塞
- Secrets Guard：禁止把 Token/密钥写入仓库与文档
- Writeback Gate：结构/规则变更必须记录到 CHANGE_LOG
