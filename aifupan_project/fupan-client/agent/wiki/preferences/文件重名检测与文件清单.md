# 文件重名检测与文件清单（协作防冲突）

## 目标

- 在提交前（pre-commit）对**新增文件**执行“重名检测”，降低多人协作时因为命名重复导致的冲突与误覆盖。
- 区分“新增文件”与“覆盖内容（修改既有文件）”两类变更。
- 在检测通过后，同步更新仓库内的文件清单，确保协作可追溯。

## 落地形态

- Git Hook：`.githooks/pre-commit`
- Hook 逻辑：`scripts/git-hooks/preCommit.js`
- 文件清单生成：`scripts/file-registry/rebuild.js`
- 文件清单存放：`agent/wiki/preferences/file-registry.json`

## 检测规则（默认）

- 仅对 **staged 的新增文件**（git status = `A`）做检测
- 重名判定：按 `basename`（文件名含扩展名）与仓库内已追踪文件比对
  - 示例：新增 `index.vue`，若仓库已存在其他路径的 `index.vue`，将提示冲突
- 允许名单：`scripts/git-hooks/duplicate-allowlist.json`（可选）

## 覆盖与新增的区分

- 新增文件：`git diff --cached --name-status` 中状态为 `A`
- 覆盖内容：状态为 `M`（修改已有文件），不走“文件名重名拦截”

## 协作流程（推荐）

1. 安装 hooks：`npm run hooks:install`
2. 正常开发、`git add` 暂存改动
3. `git commit` 时自动触发：
   - 若发现新增文件重名：阻断提交并输出冲突清单
   - 若无冲突：自动更新 `file-registry.json` 并加入暂存区
4. 解决重名后再次提交

## 注意事项

- 本机制是“提交前门禁”，无法拦截 IDE 层面的“创建文件瞬间”事件；但能保证进入仓库前可发现冲突。
- 若团队需要更严格约束（例如限定目录下不得出现同名文件），可在 `scripts/git-hooks/preCommit.js` 中扩展规则。
