# 对话记忆与蒸馏摘要（可提交到仓库）

## 定义

本机制用于把“每次问答的产出”以**蒸馏摘要**的方式沉淀到仓库内，形成可审计、可协作、可随 Git 提交的知识资产，并提供“满意度计数 + 超阈值重置会话”的可执行约束。

## 适用范围

- 适用于：团队协作时需要把关键结论固化到仓库（而不是只停留在对话上下文）。
- 不适用于：希望由前端运行时代码自动捕捉并写入“对话上下文”。本仓库的落地形态以“治理资产 + 可执行脚本”为主。

## 目录与文件约定

- 蒸馏记忆根目录：`agent/wiki/preferences/qa_memory/`
- 状态文件：`agent/wiki/preferences/qa_memory/state.json`
- 会话记录目录：`agent/wiki/preferences/qa_memory/sessions/`
- 每次问答追加：写入当日会话文件（append-only）

## 蒸馏摘要格式（建议）

每条记录建议包含：

- Q：问题（原文或精简）
- A：回答（精简）
- Distilled：蒸馏摘要（面向长期复用的 3~8 行）
- Acceptance：本次需求的验收点（可选）
- Satisfied：是否满足（true/false）
- Next：下一步动作（可选）

## 满意度计数与重置规则

- 每次记录可携带 `satisfied=false` 表示“不满足要求”
- 当连续/累计“不满足次数”超过阈值（默认 4 次）：
  - 自动创建新会话（新的 sessionId）
  - 状态文件写入 `reset_required=true`
  - 后续回答应按“新会话模式”处理：**忽略旧对话上下文，仅依赖仓库内可追溯资产**

说明：

- “重启新的对话窗口”属于对话平台能力，仓库无法强制打开新窗口；这里用 `reset_required=true` 作为团队协作的“硬信号”。

## 提示词工程（团队可复用）

建议把以下片段作为团队统一的“协作提示词”附加到智能体指令中（或作为任务开始时的约束声明）：

```
你需要维护仓库内的对话蒸馏记忆（agent/wiki/preferences/qa_memory）。
每次交付后，产出一条 Distilled 摘要（3~8 行）并更新会话记录。
本次是否满足用户要求由用户或调用脚本参数给出；若不满足则 fail_count +1。
当 fail_count > 4：将 reset_required=true，创建新会话，并从这一刻起忽略旧对话上下文，只以仓库文件为准继续处理。
```

## 推荐执行方式（脚本）

- 记录一次问答：`npm run qa:log -- --q "..." --a "..." --distilled "..." --satisfied true`
- 标记不满足：`npm run qa:log -- --q "..." --a "..." --distilled "..." --satisfied false`
- 手动重置：`npm run qa:reset`

脚本会维护：

- `state.json`：当前 sessionId、不满足计数、是否需要 reset
- `sessions/<sessionId>.md`：追加写入问答蒸馏记录
