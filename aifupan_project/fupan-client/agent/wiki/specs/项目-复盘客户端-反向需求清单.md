# 项目-复盘客户端-反向需求清单

## 本文档用途

- 以“业务域 -> 功能点 -> 代码证据 -> 隐含约束 -> 风险与待确认项”的方式，整理当前前端代码已经落地的需求清单。
- 供后续需求分析智能体直接继续做范围评估、风险识别、疑点追问与开发成本预估。
- 补足《项目-复盘客户端-反向需求总览》中无法展开的细节。

## 阅读说明

### 结论级别

- `A`：已在路由、页面、组件、接口中形成完整证据链
- `B`：代码中有明显实现，但规则可能部分依赖接口返回或后端约束
- `C`：从命名和局部逻辑可推断，但需结合 PRD/接口二次确认

### 证据锚点类型

- 页面入口：`src/views/modules/*`、`src/views/pages/*`
- 复用骨架：`src/views/commonComponent/*`、`src/components/*`
- 接口聚合：`src/utils/request-api-back.js`、`src/utils/request-api-client.js`
- 共享状态：`src/store/index.js`
- 行为协议：`src/mixins/*`

## 一、工作台与基础框架

### 1. 登录、版本选择与公开入口

- 需求点：支持登录、版本选择、404、视频号授权结果、官网云空间页、在线分享页等公共入口。
- 主要证据：`src/router/index.js`、`src/views/pages/login`、`src/views/pages/versionSelection`、`src/views/pages/onlineAnalysis`、`src/views/pages/contrastOnlineAnalysis`、`src/views/pages/aiShare`
- 结论级别：A
- 推断说明：
  - 项目既有登录后工作台，也有无需完整登录态即可访问的公开或分享页面。
  - 分享页不是单一 PDF/图片导出，而是完整页面级展示能力。
- 隐含约束：
  - Web 环境存在路由白名单，不是所有业务页面都允许公开访问。
  - 标题、返回壳、公开访问布局与登录后主壳不同。

### 2. 主布局与动态菜单

- 需求点：登录后采用统一桌面布局，左侧菜单驱动全局导航，顶部标题区承载返回、页签、用户信息、网络状态等。
- 主要证据：`src/views/layout/index.vue`、`src/views/layout/common/left/nav.vue`、`src/views/layout/common/title/title.vue`、`src/assets/json/menu.json`
- 结论级别：A
- 推断说明：
  - 菜单是系统级信息架构源，不是仅供展示。
  - 业务页面路由与菜单数据是同源维护关系。
- 隐含约束：
  - 新需求若要进入主工作台，通常需要同时接入 `menu.json`、Layout、权限与 title。
  - `AGENT`/`PURE` 版本对菜单可见性有显著影响。

### 3. 页签、缓存与返回定位

- 需求点：系统需要维持多页签感知、页面缓存、返回路径与页签恢复。
- 主要证据：`src/mixins/tabs.js`、`src/mixins/common.js`、`src/store/index.js`、`src/views/modules/system/index.vue`
- 结论级别：A
- 推断说明：
  - 不是简单 SPA 页面切换，而是接近桌面客户端的“有上下文恢复”的工作方式。
- 隐含约束：
  - 需求评估时不能只看当前页面，还要看离开/返回/缓存状态是否受影响。

## 二、直播间管理与录制控制

### 1. 直播间列表

- 需求点：以列表方式管理主播/直播间，查看当前直播、录制状态、历史、基础信息与部分衍生能力入口。
- 主要证据：`src/views/modules/dataAnalysis/index.vue`、`src/assets/json/menu.json` 中 `/dataAnalysis`
- 结论级别：A
- 已实现功能点：
  - 查看主播列表
  - 查看录制中状态与录制历史
  - 热度榜入口
  - 行业/知识库/数据诊断等相关运营入口
  - 与录制控制、检测状态、自动上传云空间联动
- 隐含约束：
  - 页面明显读取全局录制态与用户资产信息
  - 客户端运行能力与页面展示强耦合

### 2. 添加主播/直播间接入

- 需求点：支持多平台主播接入，至少覆盖抖音、快手、视频号。
- 主要证据：`src/views/modules/addCompere/*`、`menu.json` 中 `/addCompere` 及其 children
- 结论级别：A
- 已实现功能点：
  - 平台选择
  - 主播表单
  - 状态提示弹窗
  - 录制配置
  - 视频号授权/特殊弹窗流程
- 推断的产品目标：
  - 将不同平台直播源统一接入本系统进行后续录制与分析
- 待确认点：
  - 不同平台在字段、授权与录制能力上的差异细则仍需结合接口/后端确认

### 3. 客户端录制与检测控制

- 需求点：支持本地客户端控制录制、停止录制、检测状态、视频相关本地能力。
- 主要证据：`src/utils/request-api-client.js` 中 `compere/video/setup` 相关接口、`src/store/index.js` 中录制态字段
- 结论级别：A
- 已实现功能点：
  - 录制控制
  - 检测状态维护
  - 本地客户端信息读取
  - 自动上传云空间
  - 切版/版本切换限制
- 隐含约束：
  - Web 环境无法完全替代客户端能力
  - 某些行为依赖本地服务端口与 C# 推送桥

### 2. 细分上传类型

- 需求点：上传分析至少分为四类：视频分析、文案预审、切片复盘、短视频切片。

### 3. 文件分析详情/AI/只读

- 需求点：上传内容进入分析后，也能查看详情、进入 AI 助手与只读页。

### 3. 复盘案例

- 需求点：存在“案例/示例”型页面，便于展示标准分析结果或教学样例。
- 主要证据：`src/views/modules/example/*`
- 结论级别：B

### 4. 屏保页

- 需求点：客户端存在屏保或待机型页面。
- 主要证据：`src/views/modules/system/restScreen/index.vue`
- 结论级别：B

## 十三、跨域公共能力

### 1. 双通道请求体系

- 需求点：前端必须同时访问云后端与本地客户端服务。
- 主要证据：`src/utils/request-back.js`、`src/utils/request-client.js`、`src/utils/request-api-back.js`、`src/utils/request-api-client.js`
- 结论级别：A
- 影响：
  - 很多需求不是纯前端页面问题，而是环境切换与 API 源切换问题

### 2. 环境识别与差异显隐

- 需求点：系统需区分客户端、本地 Web、云空间、分享页、示例页等多种来源环境。
- 主要证据：路由守卫、分析页、权限 mixin、近期云空间弹幕问题修复上下文
- 结论级别：A
- 风险提示：
  - 若功能显隐只依赖 `versionType` 而忽略 `source`，容易在云空间失效

### 3. 版本类型与套餐等级门禁

- 需求点：功能开放与 UI 可见性依赖版本和会员等级。
- 主要证据：`src/store/index.js` getters、`nav.vue`、`auth.js`、升级组件
- 结论级别：A

### 4. 列表页统一协议

- 需求点：列表能力需要统一搜索、分页、删除、渲染规范。
- 主要证据：`src/components/coreTable/index.vue`、`src/mixins/table.js`
- 结论级别：A

### 5. 分析结果统一模型

- 需求点：不同来源的分析结果要归一到统一前端数据结构消费。
- 主要证据：`src/mixins/analysisMixin.js`
- 结论级别：A
- 影响：
  - 后续新增分析指标时，通常要看是否需要补 `sentenceMarkData` 映射

## 十四、隐含的非功能需求

### 1. 可扩展性需求

- 代码中大量使用动态菜单、插槽骨架、mixins、统一 AI 渲染，说明产品需要较快扩展新页面、新板块和新分析项。

### 2. 降级与只读需求

- 存在大量只读详情、分享访问、升级提示、权限裁剪，说明系统必须支持“看得到但不一定全能操作”的降级体验。

### 3. 持续演进需求

- 监控报告、ROI、新 AI 能力持续加到既有工作台，说明产品演进方式偏增量拼装，而非大版本重构。

### 4. 运营可售卖需求

- 版本、套餐、升级、邀请、活动页、二维码弹窗等说明系统天然服务于商业化转化。

## 十五、后续需求评估时必须先问的几个问题

1. 该需求属于哪条业务主线：直播管理、复盘、文件分析、云空间、AI、短视频、设置？
2. 是否最终落在既有详情工作台中？
3. 是否受 `client / online / webOnline / share / example` 环境差异影响？
4. 是否受 `PURE / AGENT` 或套餐等级影响？
5. 是只改页面展示，还是会影响 `analysisMixin`、API 聚合层、store 与跳转语义？
6. 是否需要同步覆盖只读页、分享页、云空间页、AI 助手页？

## 十六、待继续确认的问题清单

- `aiAgent` 入口的完整产品定位，是纯引导页还是长期工作台首页？
- `shortVideo/intelligence` 的具体业务目标、核心指标与后端契约。
- 监控相关多种指标（质检/巡检/还原度）之间的准确边界与口径。
- 不同套餐与版本在各业务域中的精细权限矩阵。
- 分享页与在线页在导出、AI 内容、只读权限上的差异化规则。

## 十七、对需求分析智能体的建议用法

- 先读《项目-复盘客户端-反向需求总览》，建立全局地图。
- 再按目标业务域跳读本页对应章节，提取功能点、证据和隐含约束。
- 若要评估成本，优先排查是否会同时影响：
  - `menu/router`
  - `views/modules`
  - `analysis-item / controlTabs / DiscernSearchContainer`
  - `analysisMixin`
  - `$httpBack/$httpClient` 聚合层
  - `store` / 权限 / 环境判断

## 结论

- 当前代码已经沉淀出一套可被系统性反推的产品结构，且“复盘详情工作台”是其最核心的能力中枢。
- 这份清单最适合作为后续需求评估、范围识别、方案选型与开发成本分析的基础资料。
- 真正需要警惕的不是“有没有功能”，而是“新增需求会不会跨环境、跨版本、跨详情骨架、跨 AI/监控链路扩散”。
