# branch_version_tracker

## 本技能用途

- 在 `dev-*` / `test-*` / `reslease-*` 分支下自动追踪版本变更记录，确保开发过程可追溯、版本功能明细可验收。

## 适用场景

- AI 检测到当前分支为 `dev-X.Y.Z.W` / `test-X.Y.Z` / `reslease-X.Y.Z` 格式时自动触发

## 触发条件

- 当前 Git 分支名匹配以下模式之一：
  - `dev-*`（功能开发微分支，如 `dev-2.6.2.1`）
  - `test-*`（测试集成分支，如 `test-2.6.2`）
  - `reslease-*`（预发布/候选分支，如 `reslease-2.6.2`）
- `aiDev-*` 分支不触发本技能

## 输入

- 当前 Git 分支名（通过 `git branch --show-current` 获取）
- 本次任务预期修改的文件列表

## 输出

- 自动维护 `docs/版本开发目录/X.Y.Z.md`（dev 分支）
- 自动维护 `docs/版本变更/X.Y.Z.md`（test/reslease 分支）
- 重复分支冲突检测结果（仅 dev-* 分支）

## 核心流程

### 步骤 1：检测当前分支类型并解析版本号

```
1. 执行 git branch --show-current 获取分支名
2. 匹配分支前缀：dev / test / reslease / aiDev
3. 若为 aiDev-* → 标记为 Agent 自动任务，终止流程
4. 解析大版本号（X.Y.Z）和功能序号（W）
```

**大版本解析算法：**
- 去除前缀（dev- / test- / reslease-）
- 取前 3 段数字作为大版本（X.Y.Z）
- 第 4 段数字作为功能序号（仅 dev 分支有）

### 步骤 2：dev 分支处理

```
1. 检查 docs/版本开发目录/X.Y.Z.md 是否存在
   - 不存在 → 创建文件，写入基础结构：
     # dev-X.Y.Z 大版本开发记录
   - 已存在 → 继续下一步

2. 检查当前功能分支 X.Y.Z.W 分支 是否已记录
   - 在文件中搜索 ## X.Y.Z.W 分支
   - 未找到 → 追加空记录模板：
     ## X.Y.Z.W 分支
     **功能名称**：待补充
     
     **变更时间**：<当前日期>
     
     **变更文件**：待补充
     
     **功能描述**：待补充
     
     **合并状态**：开发中
     
     ---
   - 已找到 → 继续下一步

3. 每次提交时更新记录
   - 更新「变更文件」列表
   - 更新「功能描述」
```

### 步骤 3：test/reslease 分支处理

```
1. 提醒用户：代码变更需更新 docs/版本变更/X.Y.Z.md
2. 提交时自动将变更写入「变更明细」表格
3. 若为合并提交（来源 dev-X.Y.Z.W）：
   - 读取 docs/版本开发目录/X.Y.Z.md 中对应功能描述
   - 摘要写入 docs/版本变更/X.Y.Z.md 的「变更明细」表格
   - 同步写入/更新「版本功能明细」表格
   - 更新 docs/版本开发目录/X.Y.Z.md 中的合并状态
```

### 步骤 4：重复分支冲突检测（仅 dev-* 分支）

```
1. 读取 docs/版本开发目录/X.Y.Z.md
2. 解析出同一大版本下其他 dev- 分支的变更文件列表
3. 将本次任务预期修改的文件与其他分支变更文件做交集比对
4. 无冲突 → 继续执行
5. 有冲突 → 暂停并提醒用户：
   ⚠️ 重复分支变更提醒
   当前分支：dev-X.Y.Z.W（功能名称）
   与以下分支存在文件冲突：
     - dev-X.Y.Z.X（功能名称）：冲突文件 xxx.vue
     - dev-X.Y.Z.Y（功能名称）：冲突文件 yyy.js
   建议：请确认是否需要先合并这些冲突分支，或当前功能是否应等待上述分支完成后再开发。
   请输入"继续"忽略提醒并继续执行，或输入"切换"切换到指定分支。
```

**豁免规则：**
- `aiDev-*` 分支不检测
- 同大版本下仅有当前分支时不检测
- 用户明确要求跳过时不检测

### 步骤 5：合并时处理

当检测到 `dev-X.Y.Z.W` 合并到 `test-X.Y.Z` 或 `reslease-X.Y.Z` 时：

```
1. 读取 docs/版本开发目录/X.Y.Z.md 中 X.Y.Z.W 分支 的功能描述
2. 摘要写入 docs/版本变更/X.Y.Z.md 的「变更明细」表格
3. 同步写入/更新「版本功能明细」表格
4. 更新合并状态为 已合并至 test-X.Y.Z 或 已合并至 reslease-X.Y.Z
```

## 版本功能明细维护规则

| 场景 | 操作 |
|------|------|
| dev 分支合并到 test/reslease（新功能） | 在版本功能明细中**新增一行** |
| 功能从当前版本移除 | 将对应行标记为 `~~已移除~~` 或直接删除 |
| 功能更新/增强 | 更新对应行的「功能概述」 |
| 上一版本继承功能（未改动） | 保留在明细中，不做标记 |

## 关键约定

- `aiDev-*` 分支不做任何自动记录操作
- dev 分支的开发记录存放在 `docs/版本开发目录/`，不在 `docs/版本变更/`
- test/reslease 分支的变更记录在 `docs/版本变更/`，来源为当前分支代码变更，非 dev 分支提取
- 版本号一致性校验：若版本号与分支不一致，阻止提交并清理版本文档修改
