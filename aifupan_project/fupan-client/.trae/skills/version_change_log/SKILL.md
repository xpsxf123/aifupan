# 版本变更记录写入（version_change_log）

## 触发（必须调用）

- 任何代码修改任务完成后，需要写入 `docs/版本变更/<版本号>.md` 时
- 用户明确要求"更新版本变更记录"时
- 任务涉及需要追踪的代码变更时

## 执行流程（严格按顺序）

### 步骤 1：获取 Git 分支号（强制新终端）

```
使用 RunCommand 工具，必须指定 target_terminal='new'：
  command: git branch --show-current
  cwd: <项目根目录>
  target_terminal: 'new'
```

从输出中提取分支名，按规则提取版本号：
- 去除前缀：`test-`、`reslease-`、`release-`
- 示例：`test-2.6.2.3` → `2.6.2.3`
- 示例：`reslease-2.6.2.2` → `2.6.2.2`

### 步骤 2：验证版本文件

确认 `docs/版本变更/<版本号>.md` 文件存在。若不存在则创建，并写入基本结构：

```markdown
# <版本号> 变更记录

## 目录

（待补充）

## 变更明细

| 记录时间 | 功能变更标题 | 功能变更模块 | 功能变更文件 | 功能变更详细内容（简洁） |
| --- | --- | --- | --- | --- |
```

### 步骤 3：追加变更条目

在表格末尾追加一行，格式：

```
| <YYYY-MM-DD> | <功能变更标题> | <模块> | <文件路径1><br><文件路径2> | <功能变更详细描述> |
```

注意：
- 文件路径使用 `src/` 开头的相对路径，多个文件用 `<br>` 分隔
- 功能描述要简洁（一句话概括做了什么）
- 时间使用当天日期

### 步骤 4：更新目录

在「## 目录」下补充本次变更的简短摘要条目。

## 核心约束（严禁违反）

1. **必须新终端**：获取 Git 分支号时 `target_terminal` 必须设为 `'new'`，严禁复用已有终端
2. **版本一致性**：写入的版本号必须与 Git 分支提取的版本号完全一致，不一致则阻止写入
3. **追加不覆盖**：只能在表格末尾追加新行，不修改已有条目
4. **文件路径准确**：确认每个文件路径在项目中真实存在
