# 多 Agent 提示词工程兼容补丁

## 目标

在不复制多套提示词工程的前提下，让不同 Agent 工具（Claude Code / Trae / Codex / 其他 IDE Agent）都能稳定访问同一套提示词工程目录，并具备“自动加载基础规则 + 按索引深入”的一致行为。

## 输入（执行前必须确认）

1. **单一来源目录名**（示例：`agnet/`、`agent/`、`.agent/` 三选一）
2. **目标工具/Agent 列表**（例如：Claude Code、Trae、Codex）
3. **该工具的“自动读取规则”**（必须自检回答）
   - 会读哪些入口文件？（根目录 / 工具目录 / 子目录）
   - 是否支持规则目录？（例如 `.claude/rules/`）
   - 是否支持 hooks？支持哪些事件？（SessionStart / PostToolUse 等）
   - 是否支持入口文件 import/include 语法？

## 输出（本技能交付物）

### A. 通用补丁资产（跨工具可复用）

1. `BOOTSTRAP.md`（统一入口与读取导航器）
2. 兼容设计文档（解释“单一来源 + 入口桥 + 自动注入 + 执行后检查”的抽象方法）
3. 补丁模板包（包含清单、适配器检查表、示例配置）

### B. 工具适配器（每个工具一份）

对每个目标工具生成一套“适配器资产”，但必须满足：

- 适配器只做“发现层桥接”，不承载长期业务知识
- 适配器必须把工具的默认加载链路引导回 `BOOTSTRAP.md`
- 若工具支持 hooks，必须在：
  - `SessionStart` 注入基础治理摘要（防止只读入口、或 compact 后丢规则）
  - `PostToolUse` 执行后做文档维护检查（防止改完治理文件不写 CHANGE_LOG/POLICIES）

## 执行流程（必须按顺序）

### 1) 建模：抽取“工具入口读取规则”

输出一张表（每个工具一行）：

- 入口文件层级（根 / 工具目录 / 子目录）
- 规则目录是否支持
- hooks 是否支持与可用事件
- 是否支持 include/import

### 2) 生成“桥接分层方案”

固定四层（不可省略概念）：

1. 单一来源层（真实知识与规则）
2. 统一引导层（BOOTSTRAP）
3. 工具桥接层（入口文件/规则目录）
4. 自动化兜底层（SessionStart / PostToolUse hooks）

### 3) 落地补丁模板

在 `docs/提示词设计-多种agent工具提示词工程兼容/patch/`（或目标项目对应目录）生成：

- `agent-bridge.manifest.sample.json`
- `adapter-checklist.md`
- `README.md`

### 4) 为每个工具生成适配器文件

要求：

- 根入口：简短摘要 + 关键规则内联（禁止只写路径映射）
- 工具目录入口（若工具支持）：详细配置 + 强制继续读取
- 规则目录（若支持）：拆分成短规则文件，主题边界清晰
- hooks（若支持）：实现 SessionStart + PostToolUse

### 5) 回写治理记录

涉及规则/技能/索引/桥接层/兼容机制的变更必须更新：

- 单一来源 `CHANGE_LOG.md`
- 必要时补充 `POLICIES.md`

## 验收清单（必须全部通过）

1. 工具启动后是否**自动**获得“单一来源目录是谁”的事实？
2. 工具是否**不需要用户显式要求**也能继续读取 `BOOTSTRAP`？
3. `compact/恢复` 后是否还能拿到基础治理摘要？
4. 修改治理文件后是否能收到“文档维护检查”提醒？
5. 项目是否仍然只维护一套提示词工程单一来源（没有多套副本）？
