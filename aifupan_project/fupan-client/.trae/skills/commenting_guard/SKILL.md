# 注释补齐（commenting_guard）

## 触发（必须调用）

- 生成/修改代码时，发现未包含“文件头功能说明”（中文）
- 生成/修改代码时，发现函数/对象缺少标准 JSDoc（@description/@param/@returns）
- 生成/修改 `.vue` 文件时，缺少对复杂业务流程的关键步骤解释（影响后续维护与 AI 升级理解）
- 用户明确要求“补注释 / 注释不符合规范 / 强制注释”

## 目标

- 让代码具备可维护、可升级、可被 AI 理解的注释结构
- 避免机械逐行注释造成文件膨胀；只在复杂逻辑或关键步骤加单行注释

## 输出要求（执行清单）

1) 文件头
- `.js/.ts`：在第一行附近增加 JSDoc 文件头注释（中文），说明：用途/入口/关键依赖/注意事项
- `.vue`：文件最顶部增加 HTML 注释说明（中文）；在 `<script>` 内再补一段 JSDoc 文件头注释（中文）

2) 函数与对象 JSDoc
- 对所有新增/修改的函数补齐 JSDoc：
  - `@description`：一句话说明职责
  - `@param`：参数含义与类型（能写就写）
  - `@returns`：返回含义与类型
- 对关键对象（如 api 模块/状态映射/配置常量）补齐 JSDoc，说明字段语义与约束

3) 复杂逻辑单行注释（重点）
- 对以下场景补充单行注释（中文）：
  - 多分支状态机/状态映射（例如 reportStatus、monitorType 映射）
  - 接口返回兼容与字段归一化（例如 summary: string -> JSON）
  - 批量接口优先、单条接口兜底的请求策略
  - 定时器/轮询/异步并发控制
  - 权限/配额 Guard 的判定链路

4) 风格约束
- 注释使用中文
- JSDoc 必须标准化（不要用随意的块注释替代）
- 不新增无意义注释（比如 “定义变量 x” 这类噪音）

## 示例模板

### JS 文件头
```js
/**
 * @description 后端 API 聚合封装：统一管理 backApi 的接口路径、请求方式与数据归一化逻辑。
 * 说明：本文件包含多个业务模块（如 scriptMonitor），在接口字段变更时需要同步更新解析与调用方取值。
 */
```

### Vue 文件头
```vue
<!--
@description 录制列表页：包含录制列表检索、对比、AI 监控报告（话术质检/互动巡检/还原度）入口与状态展示。
注意：本页面逻辑较重，修改 AI 监控相关字段时需同步对齐 request-api-back 的接口归一化逻辑。
-->
```
