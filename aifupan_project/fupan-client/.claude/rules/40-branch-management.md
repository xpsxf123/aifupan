# Branch Management（代码开发分支策略）

本规则文件始终生效，用于在执行代码开发任务前确保分支选择符合项目规范。

## 代码开发任务前置检查（MUST）

在执行任何代码修改前，MUST 按以下顺序检查分支信息：

### Step 1: 分支解析

| 任务中的分支信息 | 行为 |
|-----------------|------|
| 有明确分支名 | 切换到该分支 |
| 只有版本号无前缀（如"2.6.0.8"） | 按 `release-{version}` > `test-{version}` > `dev-{version}` 查找最高优先级 |
| 无任何分支说明 | 使用当前项目分支 |

### Step 2: 知识预检

读取 `agent/wiki/项目-复盘客户端-分支管理策略.md`（注意是 `agent/` 不是 `agnet/`），获取完整分支策略。

### Step 3: 功能存在层级查询（从上往下）

```
prod(master) → release → test → dev
```

查到某层有该功能 → 在该层开发。
全部无 → 从最低版本分支开始开发。

### Step 4: 修改方向

- 简单修改（文案等）：从最低版本分支开始，向高版本合并
- 新功能开发：从最低版本分支开始，向高版本合并
- **严禁从高版本切低功能分支**（会导致合并冲突）

### Step 5: aidev 分支创建

```
git checkout -b aidev-YYYYMMdd-NO
```

## 当前活跃版本（从低到高）

```
2.5.2.3 → 2.6.0.8 → 2.6.2.1 → 2.6.2.2
```

## 四层环境映射

| 层级 | 标识 | 分支示例 | 环境 |
|------|------|---------|------|
| 1（最低） | dev | `dev-2.6.0.8` | 本地开发 |
| 2 | test | `test-2.6.0.8` | 测试 |
| 3 | release | `release-2.6.0.8` | 预发布 |
| 4（最高） | prod | `master` | 生产 |
