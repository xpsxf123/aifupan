# 直播间管理接口对接结果说明

## 1. 已完成的对接内容

### 1.1 接口定义 (`src/http/api/liveRoom.js`)

已基于 MCP 服务中 OpenAPI 规范封装了全部 8 个接口：

- `list`: 分页查询 (`/governance/live-room/page`)
- `add`: 新增 (`/governance/live-room/add`)
- `edit`: 修改 (`/governance/live-room/update`)
- `del`: 删除 (`/governance/live-room/delete`)
- `detail`: 详情 (`/governance/live-room/detail`)
- `enable`: 启用 (`/governance/live-room/enable`)
- `disable`: 停用 (`/governance/live-room/disable`)
- `options`: 下拉选项 (`/governance/live-room/options`)

并在 `src/http/api/index.js` 中进行了统一导出。

### 1.2 页面逻辑改造 (`src/views/DepartmentAndStaff/LiveRoom/index.vue`)

结合需求文档 `FRD-直播间Tab.md` 和现有 `Curd` 组件，完成了以下联调：

**1. 列表搜索联动：**

- **所属平台**：静态下拉 (0: 抖音, 1: 快手, 2: 视频号)。
- **主播名称/ID**：将前端的 `anchorKeyword` 映射到接口的 `anchorName`。
- **所属组织**：使用 `el-cascader` 获取组织树（`apiModule.org.tree`），由于配置了 `emitPath: true`，提交时可按层级截取 `companyId`、`deptId`、`teamId` 作为精确过滤条件。

**2. 列表渲染展示：**

- 移除了原有的纯静态 Mock 数据（`constants.js`）。
- 将表格数据源通过 `apiModule.liveRoom.list` 获取。
- 对齐了字段名：`row.avatar` -> `row.anchorAvatar`，`row.name` -> `row.anchorName`，`row.account` -> `row.anchorNumber`。
- 组织展示：对齐了 `companyName` 和 `deptName`-`teamName` 的拼接。
- 管理者展示：对齐了 `managerUserInfos` 的遍历展示。

**3. 新增/编辑弹窗：**

- 接入了刚刚封装好的 `ManagerSelect` 选择管理员组件（替换了原有的下拉框）。
- 表单提交前，拦截数据：
  - 将级联选择的 `orgPath` 解析成后端的 `companyId`, `deptId`, `teamId`。
  - 编辑时正确回显级联组织的路径，以及管理人员的 ID 数组。

**4. 删除功能：**

- 采用 `el-popconfirm` 替代了直接删除，添加了二次确认交互。
- 接入了 `/governance/live-room/delete` 接口。
