# API 对接文档 — 录播 ASR 加速 accelerate（前端用）

> 适用版本：2.6.2.1-asr 分支起
> 关联：`docs/ASR加速机制-内部集成指南.md`（对内机制/其他业务复用）
> 读者：调用客户端本地 HttpServer 的 Web 前端 / 前端 AI

---

## 1. 接口概览

Web 前端调用**客户端本地 HttpServer**（与其它本地接口同一 `127.0.0.1:{port}`，端口即前端现有调用所用端口）。

- **方法 / 路径**：`GET /api/anchorvideo/accelerate`
- **参数**：`videoId`（query string，见 §2）
- **返回**：JSON `{ "accepted": true|false }`（**同步立即返回**，见 §3）
- **作用**：录播视频正在用**本地 ASR** 逐分片识别时，把该视频**尚未识别的剩余分片**切换到**腾讯云**识别（云端更快）。已识别完成的分片结果**保留**，当前正在识别的分片**不中断**。

> 定位：这是一个「让当前录播识别更快出结果」的用户主动操作按钮。仅对**录播分析**生效。

---

## 2. 请求参数

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `videoId` | query | string | 是 | 目标录播视频的 videoId（与该视频其它接口如 `cancelVideoAnalysis` 用的同一个 id）|

请求示例：

```
GET http://127.0.0.1:{port}/api/anchorvideo/accelerate?videoId=7412345678901234567
```

---

## 3. 返回

`Content-Type: application/json`

```json
{ "accepted": true }
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `accepted` | bool | `true` = 该视频 ASR **正在识别中**、加速请求已受理；`false` = 请求未生效（见下表原因）|

### `accepted=false` 的含义

| 场景 | 说明 | 前端建议 |
|---|---|---|
| `videoId` 为空 | 参数缺失 | 检查参数 |
| 该视频**尚未开始** ASR（如还在切片/下载阶段）| 加速只在识别循环真正运行时受理 | 提示「请稍候，识别开始后再试」或稍后重试 |
| 该视频 ASR **已识别完成** | 已经没有剩余分片可切 | 无需加速 |
| 该 videoId 非本机当前在飞识别的视频 | 录播一次只识别一个视频 | 确认 videoId 正确 |

> ⚠️ `accepted=true` 表示**已受理**，不代表立刻切换完成。生效时机见 §4。

---

## 4. 生效行为（前端需理解的语义）

1. **生效延迟 ≤ 1 个分片**：当前正在识别的那个分片会**先正常跑完**（不打断），**下一个分片起**才切到腾讯云。单个分片 ≤ 60 秒，故加速最长在 1 个分片内生效。
2. **仅剩余分片切换**：点加速之前已由本地识别完成的分片，结果原样保留；仅之后的分片走腾讯云。因此同一视频的最终结果可能是「前半段本地 + 后半段腾讯」的拼接。
3. **一次即可**：同一视频重复调用无副作用（幂等）；无需连点。
4. **无独立完成通知**：加速不改变识别完成的既有通知链路 —— 识别整体完成/失败仍走该视频原有的状态更新与前端刷新逻辑。前端只需在点击后根据 `accepted` 给出即时反馈即可。

---

## 5. 前端接入建议

- **按钮展示时机**：仅在录播视频「分析中 / 识别中」状态展示「加速」按钮。
- **点击反馈**：
  - `accepted=true` → 提示「已加速，剩余内容将由云端快速识别」。
  - `accepted=false` → 按 §3 表给出对应提示（多数情况可提示「识别尚未开始或已完成」）。
- **不要轮询**：本接口不是进度查询接口，点击一次即可，不要循环调用。

---

## 6. 错误与异常

- 接口本身不定义业务错误码；`videoId` 无效/非在飞等情况统一以 `accepted=false` 表达。
- 网络/服务异常（本地 HttpServer 未就绪等）由本地 HttpServer 统一异常包装返回，前端按通用失败处理即可。
