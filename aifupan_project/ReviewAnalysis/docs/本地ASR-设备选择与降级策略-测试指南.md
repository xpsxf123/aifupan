# 本地 ASR 设备选择与降级策略 — 测试指南

> 适用版本：2.6.0.6 及以后（含「仅独显」设备绑定改造）
> 面向读者：测试团队 / QA
> 关联模块：`Asr/Local/`（SenseVoiceSmall 本地引擎）、`Asr/CompositeASREngine.cs`（降级编排）、`Asr/TencentASREngine.cs`（云端兜底）

---

## 1. 一句话总览

本地 ASR 优先用 **GPU（仅独立显卡）** 跑 SenseVoiceSmall（以下简称 **SVS**）本地模型；没有合格独显时退回 **CPU**（按机器核数分档限制线程数）；当 **语言不支持 / 本地引擎不可用 / 本地识别质量过低 / 本地识别报错** 时，自动降级到 **腾讯云 ASR** 兜底。

整条链路对用户**无感**，全部自动决策，不需要人工配置即可工作。

---

## 2. 推理设备选择（GPU vs CPU）

### 2.1 设备优先级

引擎初始化时按固定优先级探测，命中即用：

| 优先级 | 设备 | 实际可用性 | 说明 |
|---|---|---|---|
| 1 | **CUDA（NVIDIA 独显）** | 当前发行包**几乎不会命中** | 发行包内置的是 DirectML 版 onnxruntime，不含 CUDA 执行提供器，探测通常直接失败并跳到下一档。保留该分支是为将来切换 CUDA 包预留。 |
| 2 | **DirectML（独立显卡）** | **双卡 / 独显机命中** | 仅在「合格独显」上启用，**绝不在核显上运行**（见 2.2）。 |
| 3 | **CPU** | 兜底，永远可用 | 无合格独显、显存探测失败、GPU 初始化失败、或本进程 GPU 已被禁用时使用。 |

### 2.2 「仅独显」判定规则（本次改造重点）

DirectML 是否启用，取决于机器上**专用显存最大的非软件显卡**是否满足阈值：

| 条件 | 判定 | 使用设备 |
|---|---|---|
| 最大专用显存 **≥ 2048MB**（默认阈值） | 判定为**独显** | DirectML，**精确绑定到该独显**（按 DXGI 枚举索引，不固定为 0 号） |
| 最大专用显存 **< 2048MB** | 判定为**核显 / 低端 GPU** | **强制 CPU**（禁用核显） |
| 显存或显卡索引**探测失败** | 无法确认为独显 | **强制 CPU**（严格策略，不退而求其次用核显） |

> **为什么不固定用 0 号显卡？** 双卡笔记本（核显 + 独显）上，0 号设备常常是核显。旧逻辑固定绑定 0 号会误用核显。新逻辑会枚举所有显卡，找出专用显存最大的那一张独显，并把推理精确绑定到它的真实索引。

> **核显为什么不用？** Intel UHD/HD、AMD APU 等核显的专用显存通常为 0~512MB（共享内存不计入），在其上跑 2.34 亿参数的 transformer 通常比纯 CPU 还慢，所以默认禁用。

### 2.3 设备选择速查表（典型机型）

| 机型 | 显卡情况 | 实际使用设备 |
|---|---|---|
| 台式机 + NVIDIA 独显（如 GTX1660/RTX 系列，≥6GB） | 独显显存 ≥ 2048MB | **DirectML（独显）** |
| 游戏本（核显 + 独显双卡） | 独显显存 ≥ 2048MB | **DirectML（独显）**，绑定到独显索引而非核显 |
| 轻薄本 / 商务本（仅 Intel/AMD 核显） | 专用显存 < 2048MB | **CPU** |
| 老旧台式机（无独立显卡） | 无合格显卡 | **CPU** |
| 任意机器，GPU 驱动/运行库不兼容 | 探测崩溃（AVE） | **CPU**（且本次运行内不再尝试 GPU，见 2.4） |

### 2.4 GPU 失败后的「粘性禁用」

如果 GPU 在推理时触发底层内存访问异常（AVE，通常是驱动 / 运行库不兼容），系统会**在本次程序运行的剩余时间内禁用 GPU**，后续所有音频直接走 CPU，避免每段音频都重复「GPU 崩溃 → 降级」。**重启应用后自动恢复**，会重新尝试 GPU（不持久化）。

## 3. CPU 线程数（核心数使用多少）

当走 CPU 推理时，ONNX 算子内并行线程数（`IntraOpNumThreads`）**按机器物理核数分档**，不会吃满 CPU（要给直播录制、UI 和用户其他软件留余地）：

| 物理核数 | 计算规则 | 实际线程数 |
|---|---|---|
| 1 核 | 取半核（下限 1） | 1 |
| 2 核 | 取半核 | 1 |
| 3 核 | 取半核 | 1 |
| 4 核 | 取半核 | 2 |
| 5 核 | 留 2 核 | 3 |
| 6 核 | 留 2 核 | 4 |
| 8 核 | 留 2 核 | 6 |
| 10 核 | 留 2 核 | 8 |
| 12 核 | 留 2 核，**封顶 8** | 8 |
| 16 核 | 留 2 核，**封顶 8** | 8 |

规则要点：
- **≤ 4 核（低端机）**：保守取「物理核数 / 2」。
- **≥ 5 核**：激进些，只留 2 核给录制 / UI / 其他软件（线程数 = 物理核数 − 2）。
- **上限封顶 8 线程**：再高核也不超过 8，避免高核机上线程调度开销。
- **下限 1 线程**：至少 1 个。
- 基于 **物理核数**（WMI `Win32_Processor.NumberOfCores`），不是逻辑核（超线程）。WMI 探测失败时回退到 `Environment.ProcessorCount`（逻辑核）。

> 该线程数仅作用于 CPU 推理路径。GPU（DirectML）路径主要算力在显卡上，线程配置同样设置但不是瓶颈。

## 4. 什么情况下使用腾讯云 ASR

腾讯云 ASR 是**兜底引擎**。下列任一情况都会用到它：

### 4.1 语言不被本地模型支持 → 全程走腾讯

SVS 本地模型**仅支持以下语言**：

| 支持本地（SVS） | 不支持（直接走腾讯） |
|---|---|
| 中文普通话（`16k_zh`）、中文医疗（`16k_zh_medical`） | 越南语、泰语、马来语、印尼语、菲律宾语 |
| 中英混合 / 拼音（`16k_zh-PY`） | 葡萄牙语、土耳其语、阿拉伯语 |
| 英语（`16k_en`） | 西班牙语、印地语、法语、德语 |
| 粤语（`16k_yue`） | …（其余所有非 SVS 语言） |
| 日语（`16k_ja`）、韩语（`16k_ko`） | |

不支持的语言在构建引擎链时**不会加入 SVS**，直接 `[Tencent]` 单引擎。

### 4.2 本地引擎实例化失败 → 从引擎链剔除，走腾讯

SVS 引擎首次创建时若失败（缺 native dll、GPU 探测崩溃等），会被**从引擎链剔除**，由腾讯兜底。腾讯引擎是延迟创建的，「只走腾讯」路径永远不会触碰 SVS 的构造，因此一定能兜底。

### 4.3 本地识别成功但质量过低 → 逐段调用腾讯替换

SVS 对**每一段音频（chunk）**识别成功后，会做质量评分（仅当引擎链中存在腾讯兜底时才评分）。命中以下**任一**规则即判为低质，触发该段的腾讯调用：

| 规则 | 判定条件 | 典型场景 |
|---|---|---|
| 规则 1：CTC 折叠率 | 非内容 token 占比 **> 0.85** | 唱歌段、纯音乐、长拖音 |
| 规则 2：字符密度过低 | 识别文本 **< 0.5 字/秒** | 长时间无人声 / 识别基本为空 |

腾讯返回结果后：
- 腾讯成功（`code=0` 且文本非空）→ **用腾讯结果替换**该段（日志 `action=REPLACED`）。
- 腾讯失败 / 异常 → **保留 SVS 原结果**（日志 `action=KEPT_SVS`），不丢数据。

> 注意：质量评分**只针对单段音频**，是「逐段择优」而非整条音频整体重识别。一条录播里可能既有 SVS 段也有腾讯替换段。

### 4.4 本地识别报错 → 下一个引擎（腾讯）

SVS 返回非 0 错误码时，编排器尝试链中下一个引擎（腾讯）。常见错误码：

| 错误码 | 含义 |
|---|---|
| 702 | 模型文件下载失败 / 超时（首次运行需下载模型，超时 10 分钟） |
| 703 | 音频解码失败 / 音频过短无法提取特征 |
| 704 | 音频时长超过 60 秒限制 |

### 4.5 后端指定引擎顺序（可选）

后端接口可返回有序引擎列表（如 `["sense-voice","tencent"]`），客户端**按列表顺序作为优先级**构建引擎链。列表为空 / null 时走上述默认路由。未知引擎标识会被跳过；若全部无效则回退默认路由。

## 5. 完整决策流程图

```
                    ┌─────────────────────────┐
                    │  开始识别（一段音频）    │
                    └────────────┬────────────┘
                                 ▼
                  语言被 SVS 支持？（4.1）
                   │ 否 → 直接走腾讯
                   ▼ 是
                  SVS 引擎实例化成功？（4.2）
                   │ 否 → 从链剔除，走腾讯
                   ▼ 是
        ┌──────────────────────────────────────┐
        │  设备选择（第 2 节）：               │
        │  CUDA?（几乎不命中）                 │
        │    → DirectML?（独显 ≥2048MB 才启用） │
        │      → CPU（核显/无独显/探测失败）    │
        └────────────────┬─────────────────────┘
                         ▼
                  SVS 识别返回码 == 0？
                   │ 否（702/703/704…）→ 下一个引擎（腾讯）（4.4）
                   ▼ 是
                  质量评分：低质？（4.3）
                   │ 是 → 调用腾讯
                   │       ├ 腾讯成功 → REPLACED（用腾讯）
                   │       └ 腾讯失败 → KEPT_SVS（留 SVS）
                   ▼ 否
                  ✅ 返回 SVS 结果
```

## 6. 测试团队验证手册（日志标记）

所有决策都会落到分析日志（`FileUtils.LogAnalysis`）。测试时**按下列标记 grep** 即可确认实际走了哪条路径。

### 6.1 设备选择相关

| 日志标记（关键字） | 含义 |
|---|---|
| `[HardwareProbe] 物理核=N, 逻辑核=M` | 探测到的核数（核对线程分档表） |
| `[HardwareProbe] 最大专用显存=XMB, 适配器#i` | 探测到的最大显存与显卡索引 |
| `[GpuProbe] 检测到独显（适配器#i, 专用显存 XMB ≥ 阈值 YMB）→ DirectML 绑定该独显` | **走了独显 DirectML** |
| `[GpuProbe] 最大专用显存 XMB < 阈值 YMB → 判定核显/低端 GPU，禁用核显，强制 CPU` | **核显被禁用，走 CPU** |
| `[GpuProbe] 未探测到独显（显存/适配器索引未知），按"仅独显"策略强制 CPU` | 探测失败，走 CPU |
| `[GpuProbe] DirectML 探测成功 (device=i)` | DirectML 在第 i 号显卡探测通过 |
| `[GpuProbe] GPU 已禁用 (本次进程内): ...` | 触发粘性禁用（本次运行后续全走 CPU） |
| `[Model] ONNX EP=DirectML, DeviceId=i` | **最终确实用 DirectML（独显 i）推理** |
| `[Model] ONNX EP=Cpu` | **最终用 CPU 推理** |
| `[Model] GPU(...)初始化失败: ..., 降级到CPU` | GPU 会话创建失败，运行时降级 CPU |

### 6.2 引擎链 / 腾讯兜底相关

| 日志标记（关键字） | 含义 |
|---|---|
| `[ASR] 构建引擎管道: [SenseVoiceSmallEngine→TencentASREngine]` | 默认路由：本地优先 + 腾讯兜底 |
| `[ASR] 构建引擎管道: [TencentASREngine]` | 仅腾讯（语言不支持 / SVS 被剔除） |
| `[ASR] 引擎 "svs" 实例化失败，已从引擎链剔除` | SVS 创建失败（4.2） |
| `[Composite-FALLBACK] chunk=... rule=collapsed_ratio ... action=REPLACED` | 唱歌/音乐段被腾讯替换（规则 1） |
| `[Composite-FALLBACK] chunk=... rule=char_density ... action=REPLACED` | 低字符密度段被腾讯替换（规则 2） |
| `[Composite-FALLBACK] chunk=... action=KEPT_SVS` | 判低质但腾讯也没救回，保留 SVS |
| `[Composite-FALLBACK] ... rule=no_tencent_engine` | 链中无腾讯，无法兜底 |
| `[ASR] 引擎降级: SenseVoiceSmallEngine 返回 code=N, 尝试下一个引擎` | SVS 报错降级到腾讯（4.4） |

### 6.3 建议测试矩阵

| 用例 | 构造方法 | 预期设备 / 引擎 | 核对日志 |
|---|---|---|---|
| 独显机 | 带 ≥2GB 独显的机器 | DirectML（独显） | `[Model] ONNX EP=DirectML` |
| 双卡机不误用核显 | 核显+独显笔记本 | DirectML 绑定到独显索引（非 0 核显） | `适配器#i`（i 对应独显） |
| 纯核显机 | 仅集显的轻薄本 | CPU | `禁用核显，强制 CPU` + `EP=Cpu` |
| 无显卡机 | 无独显台式机 | CPU | `EP=Cpu` |
| CPU 线程分档 | 不同核数机器各一台 | 按第 3 节表 | `物理核=N` 反推线程数 |
| 不支持语言 | 选越南语 / 法语等 | 仅腾讯 | `构建引擎管道: [TencentASREngine]` |
| 唱歌段兜底 | 含整段唱歌的录播 | 该段腾讯替换 | `rule=collapsed_ratio action=REPLACED` |
| 静音/无人声段 | 含长静音的录播 | 该段腾讯替换或留 SVS | `rule=char_density` |
| 超 60 秒音频 | 单段 > 60s | SVS 报 704 → 腾讯 | `返回 code=704` |
| 断网首次运行 | 清模型缓存 + 断网 | 模型下载失败 → 腾讯 | `code=702` |
| GPU 驱动不兼容 | 老旧/异常驱动机器 | 崩溃后粘性禁用 → CPU | `GPU 已禁用 (本次进程内)` |

## 7. 可配置项

DirectML 独显准入阈值可经配置文件覆盖（一般无需改动）：

- **文件路径**：`%LocalAppData%\ReviewAnalysis\Config\svs_model_config.json`
- **字段**：`directMLMinDedicatedVramMB`（整数，单位 MB）
- **默认值**：`2048`
- **示例**（把阈值降到 1024MB，让 1~2GB 显存的低端独显也启用 DirectML）：

```json
{
  "directMLMinDedicatedVramMB": 1024
}
```

> 修改后需**重启客户端**生效（硬件探测整进程只做一次并缓存）。

## 8. 常见疑问（FAQ）

**Q：为什么我的游戏本有独显却看日志走了 CPU？**
A：确认独显**专用显存 ≥ 2048MB**，并检查是否出现 `GPU 已禁用 (本次进程内)`（驱动/运行库不兼容触发粘性禁用）。也可能是 DirectML 运行库 dll 未随包发布，看 `[GpuProbe] DirectML 不可用: DllNotFoundException`。

**Q：一条录播里为什么有的段是本地识别、有的段是腾讯？**
A：这是**逐段择优**的正常行为（4.3）。口播段本地 SVS 识别，唱歌/音乐/静音段会被腾讯替换。

**Q：CPU 推理会不会把机器卡死？**
A：不会。线程数按核数分档并封顶 8（第 3 节），始终给录制 / UI 留余地。

**Q：腾讯调用次数多了会不会增加成本？**
A：质量评分阈值（CTC 折叠率 0.85 / 字符密度 0.5）是经生产数据校准的，仅唱歌/音乐/无人声等本地确实识别不好的段才会调用腾讯，纯口播不会误触发。
